# 网球逐分精剪、计分与复核

用于有连续比赛画面的网球单打录像。支持六局、四局、有占先、无占先、限时不限局、纯抢七及纯抢十；采用用户已给规则和下述默认值，只有影响结果且无法从素材核实的真实缺口才追问。不是比赛裁判或雷达测速工具。双打需要额外确认发球与接发顺序，再扩展规则，不能直接套用单打核算器。

## 工作原则：主动完成本阶段，再交付检查点

包版本 **2026.10.08-v23.9**。网球剪辑任务即使用户未手动点选本技能，也应按任务类型检索并加载；未另指定UI技能/模板/风格时，直接复用本包正式模板，禁止随机重设计。优先级为用户当前明确要求、项目已确认风格、本包默认。

- **从实际进度接续。** 先检查用户目标、已有工程和确认记录，选择尚未完成的阶段；复用已完成成果，不重做前序。首次回复通常用2–4句说明从当前起点到成片的流程、本轮产物与下一步；明确要求一口气完成、跳过介绍或上下文已表明熟悉本技能时可省略。继续、修正、回填不重复介绍。具体见[首次引导](references/onboarding.md)。
- **默认按阶段分轮交付。** 每阶段完成实质工作和自检后，明确当前阶段编号/名称、完成范围与剩余问题，说明下一阶段编号/名称及动作，并询问是否继续，等答复后推进；**阶段2有复核需求时直接完成阶段3的复核时间线与HTML，一并交付后等待用户复核**，中间不询问是否继续。其余阶段及返工沿用分轮交付，最终阶段明确全流程完成。分批仅用于阶段内执行与进度汇报；无真实阻塞时须持续完成本阶段全范围及自检，不能因批次或样例成功收工。用户明确要求“一口气完成／连续执行，只在必要时问我”时免逐阶段询问，仍报告当前与下一阶段、读细则并自检。熟悉技能、说“直接开始”只省介绍，不自动等于连续模式。
- **所有阶段共用完成门槛：完整覆盖＋规定产物＋必需自检。** 开始前读该阶段细则，收尾前按内部清单逐项核对；任一项仍可执行却未完成，就继续本阶段，不以计划、疑点列表或局部样例收工，也不等用户提醒补交规定产物。阶段接续只确认是否继续，不让用户重审既定流程、样式或清晰球。续轮从保存的[阶段记录](references/workflow.md#阶段记录与接续)开始；不靠记忆越过细则。
- **以agent视觉判读为主，补查由agent负责。** 根据原片画面与连续上下文判断分界、得分方、发球方、发次及技术事件；不开发或依赖自动查找整场分界的工具。抽帧与裁切辅助观察，检测/追踪仅辅助核验具体疑点，见[原片检查](references/source-inspection.md)。证据足够就采用并记录依据。未检查属于待办；查过仍缺关键证据才是未知。先扩大原片、看连续帧和邻接上下文，再把仍影响结果的具体疑点交用户。未知只阻塞依赖它的结论，其他工作继续；不得为显得完成而猜数。
- **沟通与产物保持精简。** 进度、结论和接续询问直接在聊天中说明，逐分复核使用既定交互HTML及复核时间线。除用户明确要求外，不为汇报或送审另造模拟声音、试听样例、演示素材或独立报告；只交付本阶段规定的产物，工作log留在内部。

## Output language / 产物语言

默认按用户主要交互语言生成全部可见产物；明确指定的渲染语言优先。English requests produce English overlays, statistics pages/matrices and HTML; Chinese requests produce Chinese artifacts. 开工或接续时记录 `outputLanguage`（`en` / `zh-CN`），在全部生成器一致传递；界面语言不替代产物语言。详见[语言选择、英文术语与接口](references/output-language.md)。不因技能说明或示例用中文而输出中文；姓名、证据原文、协议字段与复核状态不翻译。

## 先区分对象与编号

| 对象 | 含义与范围 |
|---|---|
| 剪辑段 clip | 编辑器中的片段；一分可含多个片段，一发、二发、擦网不各算一分 |
| 内部账本 / P编号 | agent工作log，记录全部候选与真实分的稳定`pointId`及证据，供后续核分与分母校验；默认不交付。有效分总数按核实后的计分资格汇总 |
| 主剪“第N分” | 当前版本有效计分顺序的`displayNumber`，连续1…N；增删合并后重生成，P号不改。分析中计分资格未定时先显示“定位 P…”而不冒称第N个有效分 |
| 人工复核子集 / R编号 | 自行回查后仍不确定的分，或计分无法与指定终局核对一致的问题整局（逐分呈现）；每行`R / P`，不复制全场账本 |
| “所有行常显” | **已选入本轮人工复核的行**不因填写状态而隐藏；不要求把全场每分送审，也不改动正在使用的审核版本和草稿 |

## 开工与接续

先读[输入与规则](references/inputs-and-rules.md)和[编辑环境选择](references/editing-environments.md)：ChatCut、Premiere Pro、本地独立流水线是并列候选，按用户指定、已有工程及实测能力选择。编辑层与[图形层](references/graphics-adapters.md)分别选择；Pr读[Premiere分支](references/premiere-pro.md)，区分CEP/ExtendScript与UXP；本地模式读[工作台](references/local-editor.md)。终端与媒体检查能力即可启动，不以Computer Use为前提；缺少通路说明具体缺口，继续可独立完成的工作，不静默换编辑器。

默认从0:0第一分第一次发球开始；结束时暂按没有未完局并用尾段与计分链核验。未知持拍手只问一次，未答暂按右手并记录假设；已知左/右手不被默认值覆盖。最终比分未知也能开始。不能把默认、推定或“presumably”写成视觉已证实，不反复确认上述默认。使用 [正式模板清单](examples/ui-manifest.json) 与 [模板说明](references/visual-templates.md)。场景、规则或画幅需要适配时保持已确认视觉语言。声明可编辑属性并在目标项目实测后才交付。主比较行与组件数量由正式清单和 [版本元数据](references/package-version.json) 核对。

## 阶段顺序与必读细则

每行是一阶段的工作与交付检查点；不适用的阶段说明原因后跳过，不交空表。已有成果先核实后复用；更正按[依赖重算](references/workflow.md#更正后的依赖)返回受影响阶段。必读链接带章节时，先读该节及其直接依赖；无章节时读全文。按当前阶段加载，遇跨阶段问题再补读对应专题。

若用户提供已逐分精剪的时间线，按[已有时间线接续](references/workflow.md#已有逐分时间线接续)核实阶段1的剪口与内部映射后进入阶段2；复用已有剪辑，再按需执行阶段3–7。

## 全流程不能越过的边界

- 先确认真实发球、首次死球和必要的落点/对手反应；练习挥拍、放弃重抛、死球后回送不凭外形变成发次或活球；真正尝试发球却挥空算失误、耗发次，但没有离拍速度。死球不清先扩展证据，主剪和复核都不能提前截断。
- 不为吻合终场比分改球果、补造缺分或虚构完整局；缺分矛盾回查整局、被删间隙与邻接边界。唯一约束逆推、视频判读、用户判罚和现场例外分别保留依据。
- 复核逐分短剪，R在P前且同分稳定；右上常显局次、发球方和发次。独立HTML默认无视频，本地工作台集成播放器；保留“人工无法确定”列、全部复核行、草稿和滚动位置。
- 已确认得分沿用；发次由阶段2核实，其余技术字段由阶段5按[统计细则](references/statistics.md)补齐。回填按[账本协议](references/ledger-and-review.md)处理null、pending/partial、人工未能归属、重打与多打，保护确认历史并继续处理缺口。
- 发次须回查删去的一发，失误才进二发，let不耗发次；与逐分判分一同由agent在阶段2核实，证据足够即采用。
- 初速估值、飞行均速、区间和补估分开；最高取中心值，不取上界。先核实事件，碰网分段；部分轨迹必须经过阶段5细则的几何、边界、留出预测和敏感性检查，不宣称雷达精度。
- UE/FE看对手来球压力，移动/站定独立判；第五页前两项只计UE内动作次数，保持中性。UE主数较少方高亮，未知单列；详细方法不挤进面板。
- **主剪短时角标与复核常显信息分开。** 主剪发次在发球前出现，出球后最多再留3秒，遇更早剪口/分界/下一发即退出；尚未计算球速也执行，不铺满整分。阶段6加入球速后共用退出帧；双误证实后改字，不重启计时。复核右上信息始终可见。
- 模板生成和脚本检查后，按[画面验收](references/presentation-and-qa.md#验证与交付)检查当前项目真实合成帧及声音，修正后再交付。

## 数据与工具

选手姓名/ID、持拍手、素材和项目标识、源路径、赛制及结果都来自当前任务。A/B仅为内部映射，不能固定某方持拍手或外观；示例中的数字和编号不作为预设。只允许明确标注的匿名复杂案例，不携带真实项目媒体ID或硬编码视频路径。

[辅助材料用法](references/helper-usage.md) 列出计算、取证、复核与模板工具；它们不代替当前编辑器能力。飞行均速、全失误动作等诊断不替代初速和UE动作主行。

执行比赛任务不授权修改技能包。必要的临时脚本放当前任务工作区；新增工具仅在用户明确要求收录且已验证实际效用后纳入技能包。

若本地文字损坏，按辅助材料用法先验证规范归档，必要时恢复本地副本；恢复不等于更新账户中保存的技能。用户仅要求修改技能时，只修改技能及维护文档，不启动比赛工作流，不改动项目时间线、现有HTML或审核草稿。
