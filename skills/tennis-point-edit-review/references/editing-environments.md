# 编辑环境选择与共同契约

先选择编辑环境，再选择图形实现。ChatCut、Premiere Pro、本地独立流水线都是一级候选；没有“先找ChatCut，找不到才考虑Pr”的顺序。用户指定或已有工程优先；未指定时按现有可用能力、可编辑性交付与媒体位置选择，不为了接入某个agent迁移工程。说明本次选择及理由，不反复追问已知偏好。

## 能力探测与分流

| 环境 | 选择条件 | 执行与必读 |
|---|---|---|
| ChatCut | 用户选择或已有项目，当前agent有其连接器/工具 | 读取项目、时间线、素材和真实参数；用当前工具实施，保持现有数据协议 |
| Premiere Pro | 用户选择或需要原生Pr工程，机器有可用Pr和可调用本地桥 | 读[Premiere分支](premiere-pro.md)，按旧版CEP/ExtendScript或新版UXP探测；XML与图形可分步接入 |
| 本地独立流水线 | 用户选择、需无交互批处理，或已明确接受缺失编辑器时的替代 | FFmpeg等完成媒体处理，复用账本和正式模板；保留可重建的剪辑计划及复核定位，不声称生成了原生Pr工程 |

任何模式都不要求agent具备桌面截图、鼠标点击或Computer Use。最低交互是终端/进程、文件读写和媒体帧检查；帧检查可通过导出PNG/视频和agent支持的媒体读取能力完成。有终端但无法查看画面/听取声音时，可准备工程和数据，却不能宣称视觉/音频验收通过。安装技能不等于安装编辑器、获得授权或已启用桥。

运行前记录：编辑器与版本/构建号、连接方式/桥版本、项目与序列、媒体读写权限、序列有理fps/画幅/色彩、源片PTS与音轨、模板/字体、帧导出与视频导出途径。能力状态分别为可用且已实测、待探测、不可用。某个工具名字存在不能升级为实测。

## 执行层不变的输入输出

- 逐分账本、采用判罚、计分审计、统计、发次与估速证据仍是共同真值。执行层只消费，不自行判球，不从截图/格式化文本反算统计。
- 源证据保留整数微秒和必要的源PTS；最终剪辑/覆盖层使用有理fps和整数帧，区间一律左闭右开。保留源到成片映射、换算误差与重采样说明。不要把微秒直接当帧，也不要把Pr ticks放入JS不安全的大整数。
- 每个片段/覆盖层有稳定逻辑ID和版本；P/R/serveId、计分状态及统计作用域随计划保留。导入产生的新host ID写入映射，不能代替业务编号。
- 主剪与必要复核是不同序列；HTML与复核序列共用映射和定位。已有审核草稿/答案不因换编辑器被覆盖或重排。
- 图形选择见[图形适配](graphics-adapters.md)。native文本、PNG和透明视频的可编辑性不同；交付时说明，不能把“Pr中可移动的图片”说成“Pr中可改分数”。
- 导入后读回实际时间线、媒体链接、时长/轨道与所有待处理操作，再检查当前合成帧及声音；接入、导入、渲染、实际验收各自记录结果。

## 失败与交付

超时可能已发生变更：先读回，不盲目重复插入。默认新建有版本的测试工程/序列；改变当前工程前保存并确认目标，不能仅凭“当前活跃序列”猜测。执行通路缺失时可继续独立取证和准备交换包；明确缺失的能力及一次性用户配置，不悄悄把指定Pr交付改成纯视频。

缺少某个服务不使网球逻辑失效。agent可以在授权工作区补充计算或渲染依赖，但不能静默更改用户编辑器、安装有广泛副作用的桥、降低系统策略或宣称未实测的替代已通过。
