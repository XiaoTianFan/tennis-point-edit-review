# 编辑环境选择与共同契约

先选择编辑环境，再选择图形实现。ChatCut、Premiere Pro、本地独立流水线都是一级候选；没有“先找ChatCut，找不到才考虑Pr”的顺序。用户指定或已有工程优先；未指定时按现有可用能力、可编辑性交付与媒体位置选择，不为了接入某个agent迁移工程。说明本次选择及理由，不反复追问已知偏好。

## 能力探测与分流

| 环境 | 选择条件 | 执行与必读 |
|---|---|---|
| ChatCut | 用户选择或已有项目，当前agent有其连接器/工具，当前运行环境为chatcut内部 | 读取项目、时间线、素材和真实参数；用当前工具实施，保持现有数据协议 |
| Premiere Pro | 用户选择或需要原生Pr工程，机器有可用Pr和可调用本地桥 | 读[Premiere分支](premiere-pro.md)，按旧版CEP/ExtendScript或新版UXP探测；XML与图形可分步接入 |
| 本地独立流水线 | 用户选择或未使用ChatCut/Pr | 使用[本地工作台](local-editor.md)的终端接口、时间线和集成逐分复核；FFmpeg导出，复用账本和正式模板 |

任何模式都不要求agent具备桌面截图、鼠标点击或Computer Use。最低交互是终端/进程、文件读写和媒体帧检查；可导出PNG/视频后用agent媒体能力查看。先核实编辑器、授权及桥可用；缺少画面/声音检查能力时继续准备工程和数据，明确待验项并补齐验收通路后检查。

Pr任务先核实自身操作能力：无Computer Use时请用户预先启动Pr并创建或打开工程；所有agent均须先询问`.prproj`保存位置，已明确提供则沿用。安装、连通、导入和实际合成验收分别证明。

先复用现成基础设施，确有能力缺口才补充适配；可采用原生MOGRT、透明PNG/视频等格式保持已确认视觉语言，不要求各环境执行相同JSX。Pr默认混合图形：简洁信息优先原生可编辑，复杂统计可由正式模板渲染；逐项声明可编辑属性和待验能力。指定Pr时可先交待导入包，不能静默改为仅交视频。

运行前记录：编辑器与版本/构建号、连接方式/桥版本、项目与序列、媒体读写权限、序列有理fps/画幅/色彩、源片PTS与音轨、模板/字体、帧导出与视频导出途径。能力状态分别为可用且已实测、待探测、不可用；通过下述独立测试与读回后，才登记已实测。

## 执行层不变的输入输出

- 逐分账本、采用判罚、计分审计、统计、发次与估速证据仍是共同真值。执行层只消费，不自行判球，不从截图/格式化文本反算统计。
- 源证据保留整数微秒和必要的源PTS；最终剪辑/覆盖层使用有理fps和整数帧，区间一律左闭右开。保留源到成片映射、换算误差与重采样说明。不要把微秒直接当帧，也不要把Pr ticks放入JS不安全的大整数。
- 每个片段/覆盖层有稳定逻辑ID和版本；P/R/serveId、计分状态及统计作用域随计划保留。导入产生的新host ID写入映射，不能代替业务编号。
- 主剪与必要复核是不同序列；HTML与复核序列共用映射和定位。已有审核草稿/答案不因换编辑器被覆盖或重排。
- 图形选择见[图形适配](graphics-adapters.md)。native文本、PNG和透明视频的可编辑性不同；交付时说明，不能把“Pr中可移动的图片”说成“Pr中可改分数”。
- 导入后读回实际时间线、媒体链接、时长/轨道与所有待处理操作，再检查当前合成帧及声音；接入、导入、渲染、实际验收各自记录结果。

## 失败与交付

超时可能已发生变更：先读回，不盲目重复插入。能力测试使用独立测试工程/序列；正式工作接续用户指定的工程与序列，改变前保存版本并核实目标，不能仅凭“当前活跃序列”猜测。执行通路缺失时可继续独立取证和准备交换包；明确缺失的能力及一次性用户配置，不悄悄把指定Pr交付改成纯视频。

缺少某个服务不使网球逻辑失效。agent可以在授权工作区补充计算或渲染依赖，但不能静默更改用户编辑器、安装有广泛副作用的桥、降低系统策略或宣称未实测的替代已通过。
