# 覆盖、编号谱系与现场例外

## 原片覆盖清单（agent内部）
为正在核查的整场或问题局明确源片范围；用无重叠的连续源时间区间登记真实回合、一发失误、擦网、重抛/空挥、捡球、等待、换边及源文件缺口。每段有 reviewed、retained 与删除原因；不能用精剪成片本身充当原片已完整检查的证明。
缺分疑点须覆盖上一局最后有效分至下一局首分，包括所有被删间隙。先排查遗漏、重复、误合并和局界；未查过的范围明确标待查。source_gap表示原录像缺失证据，不等于该段没有比赛。声明已看过只能记录检查过程，不能替代真实判读。
scripts/evidence_audit.py检查区间缺口、重叠、未审范围、删除理由及有效动作的分关联。相邻区间允许共边界，采用半开区间整数微秒。多个录像用sources的显式先后关系，禁止按文件名字母顺序推断。

## 稳定编号与合并/拆分
保留pointId，不为了恢复连续编号而重编号。独立sourceOrder/sourceStartUs控制时间顺序；后补编号可能早于较小P号。审核R顺序按新版本源片顺序生成并冻结，不在填写时重排。
合并候选时保留被撤销候选和指向存续分的谱系，不能同时计两分；拆分时保留旧候选、输出分、版本和证据原因。一个旧候选的胜者不能自动复制给拆出的所有新分。agent先按源范围与已确认事实迁移；只有真正无法消解且影响结果的矛盾才针对证据询问用户。不要直接把旧版审核JSON导入新分结构。

## 未按规则完局但现场判局
分开记录真实逐分赢家、未完局小分、rulesWinner=null、rulesComplete=false和明确采用的recordedWinner。只在用户明确采用现场归属或已有本场授权时，以 exceptionType=onsite_award_before_rule_completion、exceptionConfirmed=true 和具体 exceptionNote 接续后续局分；缺少授权或理由则报告冲突，不静默补分。
本例外放在该局最后一个真实有效分上，保持原始赢分数；计分器记录局归属、清零下一局小分并换发球，不插入虚构获胜分。普通局才适用；抢七/抢十提前结束需要另行明确规则，不套用此例外。
局类统计采用声明的现场归属；分数、破发点、ACE/双误与拍长按真实逐分路径计算，现场判局不制造额外技术事件。rulesCompleteGameCount与采用的现场局数分开。说明出现在该局最后一分死球后的短尾段；移除已解决单分上的过期推测。

## 内部依赖检查
更正球果、发次归组、持拍手或出点后，agent重新核对受影响证据及全部后续比分、统计、标签与HTML定位，保留明确确认的事实。内部记录不变成更多用户必填项；复核界面和现有导出协议无需增加字段级确认按钮。
最终交付同时报告有效分数、规则完成局数、现场例外、剩余真实疑点及统计覆盖。接受的例外不是未解释冲突，也不是规则完整完局。

## 计分链执行要点

3. **建立计分链。** 同时记录画面球果、采用判罚、规则进位、现场记法及依据。逐分推进小分、局分、盘分，核对换发球、换边和局末最后有效一分。最终结果只是约束，不能为凑比分擅改球果。冲突时回查整局及邻接边界，不只询问最后一分。

## Agent 承担核查与用户工作量边界

精细证据、字段来源和依赖重算是agent的内部工作，不新增要求用户逐字段确认的表单，也不把正反手、拍数、UE/FE、站位或估速日常判读转交用户。复核页维持现有简洁结构，已确认信息复用；先自主扩大证据、整局核查和全链复算，再将少量仍无法解决且影响比分/结论的具体问题合并提交，附可检查的证据和推荐判断。
用户确认得分不等于顺带确认所有技术字段；agent在内部维护哪些结论受更正影响并自行重查，不要求用户重新审完整清晰分或整张技术统计表。用户主动要求更细审核时再扩展。
[球速异常检查](../scripts/speed_quality.py) 比较全量/有依据样本均值并提示agent复查最高候选，不产生新的用户问卷。
