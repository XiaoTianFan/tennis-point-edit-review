# 阶段取证缓存

每批提图先声明完整任务工作区 `--job WORK`（包含账本、工程和证据索引），新建的过程图片由工具放入 `WORK/.stage-cache/<stageId>/data/` 并逐文件登记。目录名、后缀或文件年龄不构成删除权限；旧比赛档案、已有图片、原片、成片、工程、统计、轨迹、PTS、标定和技能文件不能导入此缓存当作可删项。

## 读取、落盘、提升、回收

1. 按当前问题生成并实际阅读图片／拼图；`extracted`不等于已经观察。导航或重复扫帧通常不需永久保留。
2. 将本阶段观察、采用／未采用理由、未知及数值测量写入任务规范记录。重要结论依赖的关键触拍／首碰撞夹逼、轨迹与标定依据、独有标注先列入 `essentialArtifacts`，保留原始PTS、ROI、坐标与不确定度。精确结论已采用时，工具要求至少一项关键视觉证据，具体充分性由实际判读决定。
3. 在工作区保存 `observations.json`，填写本次 `stageId`、实际阅读后的 `reviewed: true`、非空 `observations`、`adopted`，以及需保留的缓存文件名列表 `essentialArtifacts`；没有必要图时明确写 `[]`。提取工具的数值索引已登记，不得将唯一数值记录放入图片缓存。
4. 调用下述 `finish`。这是新过程缓存的常规生命周期，阶段观察落盘后直接执行，不逐阶段向用户另请清理许可。工具先提升关键图到 `WORK/evidence/<stageId>/`，验证哈希，再将登记索引中的图片引用改为保留路径或 `null`；数值字段不变。其他权威记录若仍指向缓存，先改为提升后的关键图或明确的数值记录，再重试，不能删掉记录来通过检查。
5. `finish`只逐项删除其自身独占创建、内容与文件身份未变的图片；不递归删目录，不接管未登记文件。核验受保护记录和保留图，保存计划及结果。被清理的图片引用为 `null`，可用性与原名／哈希在阶段清单可查，不能当作仍存在的图片。需要重看时按源身份、原PTS与ROI重提；源不可用则保留该限制。

```sh
python scripts/stage_cache.py finish WORK/.stage-cache/STAGE --observations WORK/observations.json
```

首次执行固定 `cleanup-plan.json`；中断后同一命令（也可省略 `--observations`）接续原计划，已删文件不重复处理。修改图片、规范数据、计划或发现符号链接／junction／hardlink时停止，保留未执行项；先核实变化，不能编辑计划绕过保护。提取中断留下的已登记图片同样需保存真实的部分观察／未采用说明再结束，不能声称完整覆盖。

只在声明工作区内扫描规范引用；外部权威工程引用本批图片时，先把该图片列为关键证据并更新外部引用，或将本批目录设在覆盖这些规范文件的共同任务工作区。不要把共享库当任务根目录。此工具不清理旧档案、不改已有清理清单、不删除原片／成片，也不代替[导出后的收尾清理](cleanup.md)及其用户确认。
