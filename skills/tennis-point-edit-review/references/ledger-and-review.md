# 账本、复核与回填

一份规范账本驱动剪辑、比分与统计。每分至少记录：
- 稳定 pointId；审核版本内固定的 reviewId 与其对应关系；局次 gameNumber、必要的盘次 setNumber，以及源片顺序；源文件逻辑名称；源时间戳/帧及帧率依据；主剪和复核时间线位置。局次与双方局分分别记录，不能混用。
- 发球者、接发者、近远端；每次实际发球的 serveNumber、fault/let/valid、触拍与死球时间；重抛独立，不增 serveNumber。
- 实际观察球果、采用球果、证据来源（用户明确确认/视频判读/规则推定）、置信及历史；不能用一个字段混同所有证据。
- 出界/下网/两跳/整分重打/ACE/制胜分/其他；双误作为独立标签。若正确信息不够，留 null。
- 是否有效计分、是否纳入该统计范围及原因：正常、重打、已完局多打、练习、未完局等分开。
- 前后计分状态、规则局赢家与现场记录赢家；额外事件、未解冲突。
- 拍数、最后击球者、UE/FE、每位网前参与、非发球击球位置、估速样本及误差。
- 剪辑保留片段数组；一个 pointId 可以有擦网与最终有效发球等多个片段。

## 独立复核时间线与 HTML
必须两者同批交付，不能只说“已生成”而没有可打开文件。列表顺序应匹配复核时间线，pointId 不随顺序变更。
HTML 每条记录与复核时间线左上角统一使用“R编号 / P编号”：先 reviewId，再 pointId，二者共用同一映射。R 是审核列表编号，P 是稳定的分编号；审核期间查找定位、剪口、慢放、提示更新不改号，回填仍以 P 为键。同一分的一发、二发和擦网都沿用同一 R/P。
时间线右上角持续显示局次、“● 发球：选手ID/姓名”及当前一发/二发；HTML 每条记录也必须常显对应的局次、发球方符号和发次信息，不只在分组标题或折叠备注中显示。局次、发球方与发次均来自该分账本，不从 R/P 数字推算。普通局的局次及发球方在局内保持稳定，特殊轮换按真实发球顺序；不确定的字段单独标待核。
补充疑点和定位说明按需要临时显示在左下角，不反复替换左上 R/P；不再以左上编号和整局标题交替显示局次。完整显示边界及验收见 [画面与交付](presentation-and-qa.md)。
HTML 默认是独立的交互列表，不附带、不嵌入视频，也不需要播放器；录像在已交付的复核时间线上查看。不要为列表额外导出或转码复核视频。列表应离线独立使用，并保留明确的时间线名称和各项定位，方便对照。仅当用户另行明确要求网页内播放时，才添加视频能力。
复核时间线必须每分独立精剪，保留完整紧凑发球动作、活球过程与可辨认的首次死球，删除捡球、等待和长准备；不能用连续整局计分段替代逐分片段。计数矛盾在分析时回看整局及相邻边界，在交付时按源片顺序逐分呈现所有相关分；不能仅移除已复核条目而跳过其后的全链复算与所有分的重新核查。双误或发次疑点需要两次发球时，将两次必要动作分别短剪，剪掉中间等待，仍归同一 R/P；擦网或重抛不独立计分。边界可以比成片略宽以保存必要证据，但不能因此保留整段准备或整局素材。
每行：R编号 / P编号、常显局次、发球方符号与选手ID/姓名、发次信息、主剪/复核/源片定位、具体疑点；两列选手 ID，随后增加“人工无法确定”列，再列死球类型；得分方 A、得分方 B、人工无法确定三者互斥；七列 out/net/two_bounces/replay/ace/winner/other，单选死球类型；双误与额外多打分别勾选，附备注。
整分 replay 清除得分；serve let 不清除整分，也不重置一/二发，写分内记录。
extra 保留实际球果但不计有效分，不能假装 replay。
使用原生表格与表头，键盘可操作；本地保存以来源和账本版本隔离；无网络依赖。全部行常驻显示；复制必须包含所有行，包括未填、已复核和待逆推的行。浏览器不允许剪贴板时提供完整可选文字。
预填AI判断不得被计为本轮用户已确认；要显式复核确认或修改后提交。
保存前检查选择、互斥、草稿恢复和完整导出是否正常。

## 回填规则
校验 schema、来源、ledgerRevision、重复 pointId 与未知ID；版本不同先做字段级对照，不自动覆盖新版本。
按 pointId 合并；pending/partial 可存明确字段但整体仍待核。null 不能清掉已确认双误；明确 false 才是否认，且需记录来源。
用户批注也可能确认双误、重发或范围，但文字与结构冲突时保留矛盾并核查。
单行 resolved 不代表整局计分一致；countingIssueResolved 也不是强制通过规则检查的开关。
合并后重算全部后续计分、局盘归属、统计、显示时序及复核清单；稳定旧ID，归档旧版本，不要求用户重复审已确认清晰分。


## 人工无法归属与后续逆推
“人工无法确定”只用于用户已查看但仍无法确定这一分得分方，不能由代理预填为人工结论，也不同于尚未填写的 pending/partial。选择后清空当前得分方和会隐含得分方的 ACE/双误确认，保留其他已知死球类型及备注；不强迫用户猜选双方之一。再次选定选手、ACE 或双误时退出人工无法归属状态；整分重打也退出此状态并照常不计分。
导出包含 winnerUndetermined=true、inferenceRequired=true、status=unresolved、reviewConfirmed=true、scoringPlayerId=null、scoringPlayer=null；countsTowardScore 保持原来的计分资格，不能因为得分者未知而置为 false。若已明确为 extra，则保持不计分，inferenceRequired=false。原本未审的空行仍是 pending/partial，不能自动变成人工无法归属。
completedRows 表示已完成本轮人工复核的行数，可以包含 unresolved；另报 unresolvedRows 和 inferenceRequiredRows，不能宣称这些分已解决。提供不同于“已解决”的待逆推状态与数量，可高亮定位；不得按状态隐藏记录，复制时仍包括所有行。沿用原本的来源/账本版本草稿键，新增字段向后兼容旧草稿。
回填时归档原采用得分方，将 scoringPlayerId、winner、adoptedWinner 置空，保留观察证据与旧确认历史；禁止让旧的 AI 预填胜者继续参与计分或统计。已确认的旧判罚与新“无法确定”意见冲突时显式记录冲突，不静默抹掉历史。待归属分不参与需要胜者的统计，已独立核实的技术事实仍可保留。
之后结合已知终局总分、局分、局末边界、相邻发球轮换、换边证据、已确认逐分结果及赛制，枚举并检验可能计分路径。换边和站位是边界证据，不能单独视作分胜负的硬约束；未知规则、缺分或额外事件不得凭终局假造。只有全部有效约束下该分归属唯一，才采用为“规则约束逆推”，记录所用约束与候选解，和视频确认、人工判定分开。多个解时只采用所有解共同确定的归属，其余仍未知；无解时回查漏分、重复计分、边界和输入约束，不强行配平总分。
当前回填助手负责保留逆推需求并阻断旧得分；计分核对器是前向校验器，不是自动逆推求解器，不得声称已自动完成逆推。


## 常驻列表要求
所有后续 HTML 复核文件都保留“人工无法确定”列。全部记录自打开起常驻列表；不论未复核、选定得分方、人工无法确定、确认死球原因、已完成、待逆推、重打或额外多打，均不自动隐藏、移除、重排或跳离当前行。取消按复核状态隐藏记录的筛选；搜索只高亮与显式定位，不隐藏任何行。改变答案仅更新本行标记、进度与导出，不改变 R/P 顺序和当前滚动位置。 不把“完成即从需复核筛选中消失”视为正确交互。保留来源/版本隔离的草稿和全部已有答案；变更 UI 不重编号、不擅自重置审核进度。

## 剪辑边界反馈优先修复
死球尚未确认时，一律按可能仍为活球继续保留，沿源片向后检查并纳入下一拍、球的落点及对手的后续反应；若仍有回球，继续延伸直到明确首次死球或双方进入非比赛状态。禁止在球刚飞起、刚落地、对手尚未作出反应时截断，也不得按固定秒数或未经证实的最后一拍猜剪口。仅在死球已证实后才删除捡球和准备，不能把证据必要的后续反应误删成等待。 每分保存最后已检查的源时间、确认结束的依据和最终保留范围；画面遮挡可保持未知，不能用截断后的片段证明回合已结束。人工标记 unresolved 若备注包含落点/下一拍/反应缺失，先扩展剪口并回看，再进行约束逆推；partial 同样处理，不能假装人工已确认。修复后重排依赖图层与 HTML 时间定位，逐分交付，不保留整局等待。发球前从真实准备动作精剪，不统一机械添加数秒空等。


## 动作候选与实际发球分离
分内分别保存 actualServeEvents 与 nonServeEvents（如 shadow_swing、aborted_toss_caught），并记录源时间、触球证据和判别来源。非发球准备事件不计入发球次数、失误、拍数、有效分或统计分母。真正尝试发球却挥空另记 serve_miss：算该次失误、可能构成双误，不计实际触拍且没有球速；保存尝试时刻，不捏造触拍时刻。countsAsServeOpportunity 与 speedApplicable/included 分开记录，统计纳入仍依当前比赛范围。旧版本把非发球事件误标一发时，保留更正历史，重排真实发次，并同步 HTML、复核时间线和主剪中受影响的提示；不能让旧 serveNumbers 覆盖用户明确的文字更正。总分存在矛盾时不借调整发次暗中新增一分。

见 [覆盖与编号谱系](coverage-and-exceptions.md)：原片覆盖、候选合并/拆分及字段依赖由agent内部核查；不增加用户逐字段确认负担。

## 逐分账本执行要点

1. **建立逐分账本。** 保留源时间、帧率/时间戳和主剪、复核时间线的独立定位。稳定 pointId 不因裁剪、复核排序或删除而改变；发球尝试作为分内子事件。采用 [账本与复核协议](ledger-and-review.md)。

## 复核交付执行要点

5. **解决确实看不清的球。** 在独立复核时间线上排布片段：HTML 每条记录与复核时间线左上角统一按“R编号 / P编号”显示（先 reviewId，后 pointId），同一审核版本共用一份编号映射。时间线右上角常显“第N局 · ● 发球：选手ID/姓名 · 一发/二发”，HTML 每条记录也常显局次、同样的发球方符号与对应发次信息；局次是当前第几局，不是双方局分。必要补充信息临时放左下角；同一分内不因剪口、重发或说明切换而反复跳号，也不再用左上编号与整局标题交替切换来显示局次。记录对应主剪/原片位置、具体疑点及证据。生成可直接打开的独立 HTML 交互列表，给出文件链接和复核时间线名称；HTML 默认只承载交互列表，不嵌入、不附带一份视频，也不为它额外导出视频。局内矛盾需分析整局及邻接边界，并把相关全部候选分逐分纳入；交付时每分单独精剪，删除捡球、等待和发球间准备，禁止用连续整局计分段代替逐分片段；交付复核时间线和 HTML 必须同步。具体显示边界见 [画面与交付](presentation-and-qa.md)。

## 用户结果回填执行要点

6. **回填复核。** 按 pointId 合并而不是行号，检查版本，不覆盖已确认字段为空值。pending/partial 留待核；人工已复核仍无法归属的分使用 unresolved 与 winnerUndetermined=true，得分方留空，转入约束逆推，不当作漏审或不计分；整分 replay 不计分；额外多打与 replay 分开；未勾双误不等于否认双误。复核完毕重新全链进位、重新统计、重建依赖显示；所有行填完不等于计分冲突已解决。

## 更新既有审核页时保护答案

所有后续 HTML 复核文件都保留“人工无法确定”列。全部记录自打开起常驻列表；不论未复核、选定得分方、人工无法确定、确认死球原因、已完成、待逆推、重打或额外多打，均不自动隐藏、移除、重排或跳离当前行。取消按复核状态隐藏记录的筛选；搜索只高亮与显式定位，不隐藏任何行。改变答案仅更新本行标记、进度与导出，不改变 R/P 顺序和当前滚动位置。 更新正在使用的页面时沿用文件位置、来源/账本版本与草稿键，不清空用户已保存答案。
