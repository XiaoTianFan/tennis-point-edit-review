# 阶段衔接、重算与交付检查点

语言选择与英文术语遵循[产物语言](output-language.md)；全部可见文案按用户主要交互语言生成，明确指定的渲染语言优先。

各项判读和显示细节见入口路由的对应模块；本页规定阶段交付和前后依赖，接续确认遵循入口的分步/连续模式。

## 阶段记录与接续

除分步/连续执行外，另记录协作模式：默认`agent-dominant`；用户明确先自行标注时为`human-first`。阶段1交付或已有剪辑接续时，按[首次标注](initial-labeling.md)在agent判赢家前准备全范围HTML/工作台；人工先行交付后等其答案或切回指令，默认模式不要求用户填全场，也不多加批准点。保留初始页与后续阶段3疑点子集的独立版本、草稿和答案。

默认按阶段交付并询问是否进入下一阶段，等答复后推进。阶段2→3例外：阶段2自查后有剩余疑点或终局矛盾，直接进入阶段3，完成并验证复核时间线及所选编辑环境的审核界面后同轮交付，再等待用户填写复核意见；中间只汇报进度，不停下询问是否制作复核。无复核需求则跳过阶段3–4，在阶段2交付时询问是否进入下一适用阶段。用户明确要求连续执行时免逐阶段询问，仍报告当前与下一阶段、逐阶段读取和自检。首次环境与信息检查并入首个实质阶段，不单独占一轮；无疑点的复核/回填说明跳过原因，下一步指向实际适用的阶段。单项修正只执行受影响的工作，不重启七阶段。

沿用已有记录；没有则保存简短阶段记录：阶段/分步或连续模式、工程及账本版本、已读细则、检查范围、产物/自检、具体缺口和下一步。按局/证据分批不构成交付检查点，本阶段自主续做；未查是待办，未做完不能宣称完成。中断或真实阻塞标明未完成与剩余范围，恢复接同阶段，不把待办改名为下一阶段。下一轮核对工程/记录并读对应细则，状态过期从受影响阶段接续。

按[两项核验](inputs-and-rules.md#局归属与逐分核验)分别记录局归属与逐分链状态；仍有计分疑点就继续阶段2或3–4，不以局分吻合或空复核列表判定通过。

交付检查点简报“当前阶段与完成范围 → 产物/自检 → 具体剩余项 → 下一阶段及动作，是否继续？”；已授权连续执行免重复询问。阶段3交付当前复核界面，请用户填写并说明收到后进入阶段4回填核算，不代填答案。未完成须说明原因与剩余动作，不把计划、候选或全空表称为完成；已授权的阶段工作主动做完。最终阶段或限定任务结束时明确完成且无后续阶段。复核意见留既定界面，不另造汇报、试听或演示产物。

每轮比赛工作回复（含单项修正/回填）结束时说明当前阶段、具体未解项和下一步责任/动作；有疑点给修订复核入口，收到答案后由agent补查、推断和重算；全部解决则指明下一阶段。已授权连续执行不重复询问。

## 阶段间的证据接续
阶段顺序与产物见[入口阶段表](../SKILL.md#阶段顺序与必读细则)。阶段1为完成剪辑先判真实发球、发次和分的归组，可用发球轮换等临时判断辅助定位，依据与P映射留内部log；阶段2复用并核实，再推进比分。阶段划分规定交付顺序，当前剪辑所需判断在当前阶段完成。
阶段3、4可多轮往返，每轮保护答案并仅追加必要复核；仍有缺口时只推进不依赖它的工作。阶段5备齐数据，阶段6实时合成图层；常规agent主动整片渲染等全部分归属和统计完成获用户确认；用户在任一阶段明确要求导出时，直接导出当前版本，不强迫提前完成或确认其余阶段。

## 已有逐分时间线接续

若只有渲染成片而无工程，先走[剪口重建](rendered-video.md)恢复可编辑的候选片段，不能将其直接等同于已核实的逐分时间线。以下工程接续与成片路径都须在首次判赢家前完成[首次标注界面](initial-labeling.md)。

仅适用于用户提供已逐分剪好的ChatCut或Premiere Pro工程，且当前环境可读取和编辑该工程的情况。

- 读取指定工程与序列，保存当前版本；保留用户剪口、顺序、原声及既有图层。将现有片段、源素材入出点、变速和时间线位置映射到稳定pointId，一分的多个片段共用P号。沿用已有明确确认，其余球果在阶段2按[判读细则](adjudication.md)核实。
- 核实阶段1的剪口与内部P映射后，按入口阶段2接续自主判分、发球核查和基础图层；有必要复核时连续完成阶段3材料，之后按实际进度接续。
- 原片用于补查被剪掉的一发失误、死球证据和计分缺口；源片不可访问或映射不全时明确覆盖范围与未知，不凭剪辑顺序补造结果，也不把变速后的时间用于原速估算。默认不重剪已完成片段；发现必要证据被截断时按剪口修复规则处理，不为统计或估速恢复已删等待段。

## 更正后的依赖
| 更正类型 | 自主回查与重算范围 |
|---|---|
| 漏分、重复分、发次误归组、合并/拆分、计分资格或采用赢家更正 | 回看相关整局和邻接边界；保护编号谱系与确认历史，重新全链进位，更新局盘、计分板、依赖统计及复核版本定位 |
| 剪口遗漏落点/下一拍/对手反应 | 先扩大原片并确认首次死球，再判断球果或逆推；回映射保留片段和所有依赖图层，不重复交付原截断证据 |
| 持拍手更正 | 保留新的确认来源；回看实际触拍侧与动作后更新相关正反手数据，不能整体机械交换标签 |
| UE/FE或动作分类更正 | 回看来球压力与独立动作窗口；从事件重新汇总UE/FE、手别、UE动作、方向及相关第三拍指标；不因此改已确认得分和局分 |
| 发球触拍、初速模型或速度估值更正 | 重新确认触拍至首次碰撞前的同球证据；更新该发与引用它的补估记录、相应盘/全场聚合、最高候选及统计面板，再同步相关球速标签与大小标签退出；不因此重写已确认球果 |
| 只更改显示风格或排版 | 更新已授权模板和实例，保留数据、剪辑定位及用户复核答案；检查受影响的真实合成帧 |

以[覆盖与现场例外](coverage-and-exceptions.md)记录内部取证、谱系及重算；沿用用户已确认得分，发次在阶段2核实，其余技术字段在阶段5按[统计细则](statistics.md)补核。发现与用户确认矛盾的新证据时展示依据及影响，不静默推翻。

## 阶段检查点
按[入口阶段表](../SKILL.md#阶段顺序与必读细则)逐项核对完整覆盖、规定产物和必需自检，再按本页记录交付与接续。阶段2检查全部目标分，不能只查ACE/双误或凭终局吻合代替覆盖；有疑点连贯完成阶段3，复核视图和审核界面均可用后交付，本地不生成离线HTML。
数据矛盾返回判读/核算，显示错误修正后重查[实际合成](presentation-and-qa.md#验证与交付)；用户答案按[回填规则](ledger-and-review.md#回填规则)落地并重算，不能只读取答案而未应用。
