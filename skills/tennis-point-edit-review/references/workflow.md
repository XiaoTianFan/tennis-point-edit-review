# 阶段衔接、重算与交付检查点

各项判读和显示细节见入口路由的对应模块；本页规定阶段交付和前后依赖，接续确认遵循入口的分步/连续模式。

## 阶段记录与接续

默认每轮完成入口表中当前适用的一阶段，交付检查点并询问是否进入下一阶段，等答复后推进；所有阶段及复核返工均适用。用户明确要求连续执行时免逐阶段询问，仍报告当前与下一阶段、逐阶段读取和自检。首次环境与信息检查并入首个实质阶段，不单独占一轮；无疑点的复核/回填说明跳过原因，下一步指向实际适用的阶段。单项修正只执行受影响的工作，不重启七阶段。

沿用项目已有工作记录；没有则保存一份简短阶段记录：当前阶段/连续或分步模式、工程与账本版本、已读细则、已检查范围、产物路径与自检结果、未完成项/具体缺口、下一步。可按局或证据范围分批执行，批次结束后自主继续本阶段，不设置用户接续确认。交付前按内部清单核对本阶段全部应做项；未检查不是未知，仍有可执行待办就不能宣布阶段完成。真实阻塞或中断须标明阶段未完成与剩余范围；恢复后接同阶段，不把待办改名为下一阶段。下一轮核对项目与记录并读对应细则，状态过期则从受影响阶段接续。

检查点在聊天中简短报告“阶段N（名称）已完成 → 产物与自检 → 剩余问题 → 下一阶段M（名称）及动作，是否继续？”；不只写“已完成”或无说明地暂停。最终阶段或限定任务结束时明确已完成，无后续阶段。已授权的本阶段工作主动完成；其他问题仅限必要规则/证据缺口或人工设置。未完成时写明当前阶段、原因和剩余动作，不把计划、候选或全空待核表称为完成。复核意见放在既定交互HTML；不另造汇报文件或试听/演示产物，见入口的精简交付原则。

## 执行顺序
首次引导与信息整理 → 1逐分精剪并排入时间线 → 2判读计分与基础图层 → 3人工复核 ⇄ 4回填再核算 → 5技术统计与全量估速 → 6统计面板与球速图层 → 7合成验收。
阶段1交付完整逐分时间线，暂不计分；账本是内部工作log，作为后续核分与分母校验的依据，默认不交付。阶段2自行判分核算；发现剪口缺失时回修，不把首次精剪拖到阶段2。
阶段3、4可多轮往返，直到矛盾解决或明确记录仍无法消解的缺口；每轮保护答案，仅追加必要复核。未解球果不自动确认，后续只推进不依赖缺口的工作；阶段5备齐数据，阶段6统一渲染面板与球速图层。

## 已有逐分时间线接续

仅适用于用户提供已逐分剪好的ChatCut或Premiere Pro工程，且当前环境可读取和编辑该工程的情况。

- 读取指定工程与序列，保存当前版本；保留用户剪口、顺序、原声及既有图层。将现有片段、源素材入出点、变速和时间线位置映射到稳定pointId；一分可含多个片段，不能把每个clip直接算作一分。已有明确确认沿用，“已剪好”本身不代表球果已确认。
- 核实阶段1的逐分剪口与内部P映射，复用已剪时间线后进入阶段2：自主判赢家、发球方、发次与局界，核算比分并加入计分板、可见编号和短时发次标签。阶段3–4仅处理自行回查后的疑点或终局矛盾，可反复复核与重算；阶段5备齐统计及估速数据，阶段6制作面板和球速图层，阶段7验收。
- 原片用于补查被剪掉的一发失误、死球证据和计分缺口；源片不可访问或映射不全时明确覆盖范围与未知，不凭剪辑顺序补造结果，也不把变速后的时间用于原速估算。默认不重剪已完成片段；发现必要证据被截断时按剪口修复规则处理，不为统计或估速恢复已删等待段。

## 更正后的依赖
| 更正类型 | 自主回查与重算范围 |
|---|---|
| 漏分、重复分、发次误归组、合并/拆分、计分资格或采用赢家更正 | 回看相关整局和邻接边界；保护编号谱系与确认历史，重新全链进位，更新局盘、计分板、依赖统计及复核版本定位 |
| 剪口遗漏落点/下一拍/对手反应 | 先扩大原片并确认首次死球，再判断球果或逆推；回映射保留片段和所有依赖图层，不重复交付原截断证据 |
| 持拍手更正 | 保留新的确认来源；回看实际触拍侧与动作后更新相关正反手数据，不能整体机械交换标签 |
| UE/FE或动作分类更正 | 回看来球压力与独立动作窗口；从事件重新汇总UE/FE、手别、UE动作、方向及相关第三拍指标；不因此改已确认得分和局分 |
| 发球触拍、初速模型或速度估值更正 | 重新确认触拍至首次碰撞前的同球证据；更新该发与引用它的补估记录、相应盘/全场聚合、最高候选及统计面板，再同步相关球速标签与大小标签退出；不因此重写已确认球果 |
| 只更改显示风格或排版 | 更新已授权模板和实例，保留数据、剪辑定位及用户复核答案；检查受影响的真实合成帧 |

以 [覆盖与现场例外](coverage-and-exceptions.md) 记录内部取证、谱系及重算，不增加用户逐字段确认。用户确认得分只锁定对应事实，不能顺带确认未知技术字段；发现与用户确认矛盾的新证据时展示依据及影响，不静默推翻。

## 阶段检查点
- 精剪交付前：全片各分已按发球至首次死球及必要反应剪出、排入主时间线，剪口/原声/覆盖已查；内部log保留P与源/主剪映射。交时间线而非账本，暂不计分，不把片段数当有效分数。
- 计分交付前：对全部目标分逐项核对赢家、发球方、发次（含必要的被删发球间隙回查）、局界、计分链及基础图层，不能只查ACE/双误等特殊分。主剪每分有计分板及可见序号，每次保留发球按证据加短时标签；仅自查后真疑点保留未知并进入必要复核。终局吻合或少数叠加样例通过不代替逐分覆盖；核对出球后3秒或更早边界退出。
- 复核交付前：每分独立短剪并有充分死球证据；R/P、常显局次与发球方、发次及HTML定位同源；所有行常驻，未知列与草稿完整。
- 统计数据完成前：检查有效分与终结分类、分母及未知守恒；UE/FE依据独立来球压力；真实发球包含删去的一发，补估可追溯。五页数据、逐发估值及图层映射/时序齐备后进入阶段6。
- 图层制作完成前：五页面板与逐发球速消费同版本数据，均已进入时间线；验证出球前后、3秒或更早边界及双误状态切换，不能套用到复核常显信息。
- 最终交付前：按 [画面验收](presentation-and-qa.md) 查看当前合成画面和声音。已通过自动检查只证明被检查逻辑，不证明当前素材球果或所有分辨率的视觉表现。
