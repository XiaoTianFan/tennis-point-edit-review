# 画面与交付

## 初速统计验收
发球页在一发进球率后增加二发进球率，并显示分子/分母。发球页速度统一标“初速估算”，逐盘包含所有纳入的真实发球后再算一发、二发、整体均值与中心估值最高者。在底层可追溯报告中注明含失误与否、全量条数、轨迹/端点估算与同组模型补估数量；补估不得冒称全量视觉实测。区间上界不作为最快值。速度行不用少量抽样均速直接替代，也不因部分难测就停止模型分析或直接留下大量空项。
临时说明组件用较小字号和紧凑占幅，底部必须有明确内边距，最长实际文案也完整包含在组件内；保持计分板及发球标签已确认样式。统计整体适度紧凑，增加指标后重新检查各页文字与底注，不靠裁切或遮挡挤入。

## 剪辑
阶段1即完成全片逐分精剪并按顺序排入主时间线，检查实际剪口与原声后交付；暂不计分。P号通过片段名称/标记定位，源片映射保存在内部log；阶段2再加入计分与基础图层。
首次发球动作从完整但紧凑的动作启动开始，默认保留进入动作必要的极短预备，不包含长拍球等待。最早死球帧不能截掉，通常留几帧让观众理解落点；避免冗长拾球。
删除一发失误后，二发必须接其真实动作，不能把捡球段当二发。保留的 let 可独立成片段，但属于同一 pointId。每次重剪重新映射比分、发球标签、字幕与说明的时序。
优先通过当前编辑器的支持能力完成剪辑；没有可用编辑器时，复用[本地工作台](local-editor.md)的剪辑与复核流程。辅助脚本不直接操作项目数据库。

## 动态计分板
左下角紧凑双行，选手名、发球指示、当前局分、当前小分对齐；多盘时加已完成各盘及盘分信息，随需要适度加宽。纯抢分用整数，避免虚构普通局。
顶部“赛制/无占先 · 第N分”，N来自当前版本的[连续显示序号](coverage-and-exceptions.md)，不直接使用稳定P号；复核仍用原R/P。通过现有`rule`属性填入，不改模板结构。正常计分板不再有底部说明长行。40–40 按规则标金球或 Deuce，有占先显示 AD；局结束及盘结束在死球后进位，下分起始及时清零。
借鉴职业转播的分列、对齐和高对比当前小分，不照搬赛事Logo、特定品牌或完整配色。默认延续深蓝#142C42、标题深蓝#0A1B2B、青柠#DAF36D、白#F5F7FA及支持中文的字体；新项目优先其已确认风格。除非用户另有要求，直接采用上述风格；可生成可见样例自行核验，不例行询问是否采用，也不等待重复样式批准。
参考1080p尺寸：计分板440×132，边距约48；这是一盘紧凑示例，不是所有分辨率的硬尺寸。
主剪右上角一发/二发、擦网、双误独立显示。主剪临时争议说明可放左上，小面积，保留关键事实；以正式模板默认比例为起点，文字增加时增高并保留底部留白，避免遮住球与球员。多打期间计分板同时显示“不计分”。独立复核时间线采用下述专用布局。

### 分析期逐分定位与基础图层

阶段2在已精剪时间线上加入逐分计分板与短时发次标签；计分资格未定时，用现有文字属性显示“定位 P…”，一分多段共用P号。比分仅未知字段留空/待核，已知照填，受未知影响的后续比分也不能猜填。资格核实后改用连续“第N分”，P仍保留在内部log与定位标记中；增删合并后重建显示序号，末号等于有效分数。

主剪发次大标签在发球前出现，在已确认出球的显示起点后最多再留3秒，或于当前片段/该分结束/下一发开始的最早边界退出；**尚无球速条也执行此时限**，不能铺满长回合。阶段6加入球速时复用同一出球依据和共同退出帧，详见[逐发球速时序](serve-speed-overlay.md)。无法定位触拍时先补查，只标明具体未完成范围，不用整分常驻标签顶替；真正发球挥空按无触球例外处理。

检查可见序号切换、长回合出球后3秒边界、短球剪口和发次更换的真实合成帧。撤下错误覆盖层或少数标签样例通过只是中间步骤；须完成全部目标分的判分、发球核查及相应基础图层，仅保留自查后真疑点，才可报告阶段2完成。

## 局分与逐分复核时间线
每一分单独精剪后顺序衔接，去掉捡球、等待及长准备；分析整局不等于交付连续整局片段。需要核对整局时，交付该局所有分各自的紧凑片段和必要邻接分。同一分的一发、二发证据分别短剪，中间不保留等待，R/P 持续不变。
复核画面沿用已确认风格，三类信息各有固定位置；HTML 和 ChatCut Review Timeline 共用同一份编号、局次及发球方数据。

- **左上角：R编号 / P编号。** 固定先显示 Review 编号，再显示 Point 编号，例如“R003 / P015”（虚构示例）。HTML 每条记录的标题也必须采用完全相同的顺序和对应关系，不能一处 P 在前、一处 R 在前。R 是本次审核列表的编号，P 是逐分账本的稳定编号；二者不能互相替代。发布审核版本后，R/P 映射不因查找定位、内部剪口、重看或提示出现而变化，回填仍以 P 为键。同一分的一发、二发、擦网、慢放及内部剪口持续显示相同 R/P；不重复入场动画、不闪烁、不与整局标题或解释卡交替替换。只在进入另一分的证据时切换对应 R/P；回看旧分显示原映射。位置、字号和版式保持稳定。
- **右上角：常显局次 + 发球方 + 发次。** 使用固定信息区，例如“第2局 · ● 发球：选手甲 · 二发”（虚构示例）。每个保留的发球尝试都应显示当前是一发还是二发，不能只在主剪渲染。发球方符号使用一致的实心圆点“●”，紧邻明确的选手ID/姓名，并以“发球”文字说明含义；HTML 每条记录使用同一符号、含义与选手映射，不能仅靠颜色让用户猜是谁。局次和发球方从该局首段证据开始，贯穿回合、死球尾段、分间等待、擦网重发、慢放和临时说明的进出，不能只出现几秒或依赖左上标签切换才能看见。普通局局内保持同一发球方，按真实换发边界更新；抢七等特殊轮换则按逐分账本更新，不能误认为整段由同一人发球。
- **左下角：临时补充信息。** 需要时显示疑点、首次落点、发球归属依据、整局计数矛盾、主剪/原片定位或“分间”等短说明；随相关证据出现，说明结束即退出，不占用左上编号区或右上常驻信息区。若该位置已有计分板，在左下区域避让排布，避免覆盖数字、球或球员；无需补充时不放常驻说明卡。

### 发次与局次的切换边界
当前发球动作开始时显示其真实发次，标签贯穿对应发球及随后的回合；下一次真实发球开始才按序更新。一发失误和二发同属一分，只换发次，不换左上 R/P、局次或发球方。擦网重发保留原发次，可附“擦网”；二发失误被确认后可显示“二发 · 双误”，不能只剩“双误”而丢失发次。重抛不消耗发球机会。仅有证据需要的极短分间衔接保留时，局次和发球方保持可见，可暂不显示上一分的发次，左下注明“分间”；左上维持上一分 R/P，直到下一分证据进入。

“第N局”是当前比赛的局次标识，不等于双方局分，也不从 R/P 数字或最终比分倒推。限时单盘按比赛顺序连续标局次，多盘显示“第S盘 · 第N局”以消除歧义。只有证据进入下一局时才更新，不在上一局死球前提前进位；复核默认剪掉换边休息；必要的极短局间证据保持刚结束的局次并注明“局间”。纯抢七/抢十用相应阶段标识，不虚构普通局编号。确实无法确定的字段分别显示“局次待核”“发球方待核”或“发次待核”，保留可追溯依据，不擅自猜填；其他已知字段照常显示。

整局复核须覆盖各分的 R/P、局次、发球方与发次，不能只给整局一个标题。左上编号、右上常驻信息和左下说明分别控制显示时序；说明进出、一发转二发和跨剪口都不得触发编号重置。局次已经在右上常显，不再通过左上“R/P—第N局—R/P”交替显示局次。

## HTML 复核列表

列表只包含[人工复核子集](ledger-and-review.md#独立复核时间线与-html)；“全部行”是这个子集中的全部已发布记录。全场账本用于agent分析，不能直接批量复制成用户待审表。

以下独立HTML约定适用于外部编辑器；本地模式使用[集成工作台](local-editor.md)的播放器与左侧审核列表，并额外验收播放、定位、帧步进和剪辑操作。两种界面保留相同审核字段、行序与回填语义。

默认制作可离线打开的 interactive list（交互列表）：用户在复核时间线看录像，在 HTML 中填写判断。HTML 不需要播放器、嵌入视频、附带视频文件或视频下载链接；不为复核页重复导出或转码一份录像。只有用户另行明确要求网页内看视频时才扩展。
每一条 record 的常显信息必须包含：
- 标题按“R编号 / P编号”排列，与时间线上该分一一对应；查找定位和折叠备注不重新生成 R/P，不自动重排记录。
- “第N局”（多盘时带盘次）、“● 发球：选手ID/姓名”及对应发次信息，放在该记录始终可见的标题或摘要区；不能只依赖上一组表头，也不藏在悬停提示或折叠备注内。一条记录包含一发和二发证据时，可显示“一发→二发”；只展示最终二发时明确显示“二发”。数据不明时逐字段标待核。
- 复核时间线名称、复核/主剪/原片定位及具体疑点，方便对照录像。

局次、发球方和发次从同一逐分账本生成，不能让 HTML 和时间线分别猜测或独立计数。保留判断输入、只高亮定位的搜索、本地草稿和复制全部结果，所有行始终可见；页面不依赖视频文件、网络或本地服务即可使用。

## 统计
多盘录像在真正盘末set break选保留休息段，不在任意换边插满屏数据；末盘在所有比赛片段之后。单盘直接放结尾，优先用比赛后的捡球/收尾背景。
明确 SET STATS / MATCH STATS，五组可翻页，默认每页8秒、合计40秒；不因发球页或回合页文字多而自动延长，用户可暂停阅读。比例与字数调整，尤其11行发球页与含副文本的回合页。
AI免责声明在统计面板最后一行，删计分板底行不等于删统计免责声明。

## 阶段6：统计面板与逐发球速图层
主剪每个保留的真实发球在触球出球后，于右上现有发球标签下方显示该发初速中心估值，最多3秒，短球及时收起；保持原发球标签样式；发球前先显示一发/二发，出球后球速入场，二发失误证实后才改为双误，大标签与球速在同一帧退出。主剪共同计时上限为球速出现后3秒，不影响复核右上信息的常显要求。采用正式serveSpeed模板，同组模型值标补估。实施与源时间映射、擦网及变速处理、逐项时序检查遵循[逐发球速回填](serve-speed-overlay.md)，不新增用户复核任务。

## 验证与交付
检查实际合成帧：普通分、金球/Deuce/AD、抢七发球轮换、局盘边界前后、例外的出现/退出、最后有效分、统计五页。
确保字不裁切、徽标不挤、名字和数字清楚、辅助说明面积小；监听修改切口的原声与音量，保证无丢分、重复球、黑帧/空洞。只报告实际检查范围。
按当前阶段交付：阶段1给主剪时间线；阶段3给复核时间线与HTML链接；后续给相应图层及统计/估值覆盖。按[阶段检查点](workflow.md#阶段记录与接续)在聊天中说明当前及下一阶段并询问是否继续（已授权连续执行除外）；复核意见写入既定HTML，不另造模拟声音、试听样例或额外报告。仅报告当前剩余疑点，不提前交未到阶段的产物；局分闭环不等于全部技术项已核实。

复核专项检查：逐条核对 HTML 与时间线是否均为“R编号 / P编号”及相同映射，HTML 每条记录是否常显局次和发球方。连看同一分一发→二发、擦网重发、内部剪口、分间等待→下一分、跨局及临时说明进出，确认左上编号没有来回跳动，右上局次与发球方始终可见且在真实边界更新，发次没有漏显或误增，说明位于左下且不遮挡；抽查整局各分，不能只检查一个样例。HTML 验收只针对交互列表及定位、保存、导出，不把视频附带或播放器运行作为交付条件。仅更新技能的任务不应修改既有 HTML、时间线或用户审核草稿。


## 人工无法确定列
复核 HTML 列顺序固定为定位信息、选手A、选手B、人工无法确定、死球类型。三种得分归属选项互斥；人工未知不等于重打或额外多打。显示“已人工复核 · 待逆推”，可高亮定位但不得隐藏其他行，导出含显式标记和空胜者；已知死球原因及备注保留。验证切回选手、ACE、双误、重打、刷新恢复、行始终可见与全量复制。此需求仅改变 HTML 与协议，不要求为它改写正在审核的视频。


## 行可见性验收
所有后续 HTML 复核文件都保留“人工无法确定”列。全部记录自打开起常驻列表；不论未复核、选定得分方、人工无法确定、确认死球原因、已完成、待逆推、重打或额外多打，均不自动隐藏、移除、重排或跳离当前行。取消按复核状态隐藏记录的筛选；搜索只高亮与显式定位，不隐藏任何行。改变答案仅更新本行标记、进度与导出，不改变 R/P 顺序和当前滚动位置。 逐项选择双方得分、人工未知、死球类型、双误、已复核、重打及额外多打后，所有行数量和顺序保持不变；填写备注不改变显示范围。刷新恢复全部答案后仍显示全部记录；搜索有匹配和无匹配时都不隐藏行；只有用户显式定位才滚动。

## 尾部证据和起点验收
死球尚未确认时，一律按可能仍为活球继续保留，沿源片向后检查并纳入下一拍、球的落点及对手的后续反应；若仍有回球，继续延伸直到明确首次死球或双方进入非比赛状态。禁止在球刚飞起、刚落地、对手尚未作出反应时截断，也不得按固定秒数或未经证实的最后一拍猜剪口。仅在死球已证实后才删除捡球和准备，不能把证据必要的后续反应误删成等待。 对每个新修复的片段，先看完整保留段，再检查旧出点之后的球路、对手是否击球以及最终停止对抗的动作；用实际源时间核对最终几秒。不可用单张最后一帧或接口成功代替完整边界检查。精简起点应保留完整发球动作，去掉此前与发球动作无关的静止准备。


## 发球真实性检查
交付前逐项确认标成一发/二发的动作确有真实发球尝试证据；空挥和主动抛球接回不能显示为失误发球。复核为解释错误而保留这些动作时，显示“非发球动作 · 不计发次”，实际发球另显示正确发次；HTML 记录同样的非发球事件说明。发次未知明确写待核，不因已确认得分而连带确认发次。

五页优先复用正式模板；若自然休息尾段不够五页默认40秒，可在不动有效分的前提下用最后稳定干净画面定格延长，并检查音频淡出及定格接点，避免录制结束时触碰相机的画面。每行的计数/分母与百分比同时保留。未知手别须显示未判或覆盖说明，不能丢掉终结分类总数。



五页统一较优主值使用青柠主题色，平局与中性项目维持原白色。第五页 UE 中移动/站定击球次数放前两行；不追加定义或训练解释，未知只用紧凑计数注明。发球页保留最高初速主行，删除额外的全盘发球数/补估覆盖/最高值重复小字；回合页不追加“正反为终结拍手别”的第二行解释，未知手别仍保留原行副文本。AI免责声明继续保留。验收覆盖高值优、低值优、并列、中性与未知样本；文字完整包含在组件中，不触底。

## 主剪逐分剪口执行要点

**阶段1：逐分精剪并排入主时间线。** 从实际发球动作开始前的紧凑位置起剪，不机械保留固定时长的发球前准备；留到首次死球及必要的对手反应已可辨认。死球尚未确认时，一律按可能仍为活球继续保留，沿源片向后检查并纳入下一拍、球的落点及对手的后续反应；若仍有回球，继续延伸直到明确首次死球或双方进入非比赛状态。禁止在球刚飞起、刚落地、对手尚未作出反应时截断，也不得按固定秒数或未经证实的最后一拍猜剪口。仅在死球已证实后才删除捡球和准备，不能把证据必要的后续反应误删成等待。剪去捡球、等待、发球间准备、一发失误；保留擦网重发；双误仅保留最后一次发球。阶段2添加标签：发球前显示真实一发/二发，擦网或双误证实后才改字；阶段6回填球速并统一大小标签退出。擦网和抛球重抛不消耗新的发球机会。死球后捡球回送不算活球。

## 统计面板执行要点

**阶段6：制作统计面板。** 按 [画面与交付](presentation-and-qa.md) 核对阶段2已有的计分板、发球提示与临时说明，再制作盘末/片尾统计面板，面板与全量逐发初速使用同一份最终统计数据。默认五页各8秒；最高发球初速列为主行，第五页首两行统计 UE 中移动/站定击球的次数。使用阶段5已按[UE/FE判读标准](error-classification.md)独立判类并汇总的 UE 终结拍动作数据，不在渲染阶段重判或扩成全场逐拍移动标注。定义与训练解释留在底层，面板只呈现统计值和必要的紧凑未知计数。按指标明确的高/低优向用主题青柠色标注较优方，相同数值、无样本和描述性分布不高亮；详见统计口径。

## 实际合成执行要点

**阶段7：合成验收。** 使用当前环境支持的编辑能力，编辑后检查真实合成画面及依赖层，包括球速出现前后和3秒退出边界。工具成功不等于视觉正确。

## 统一交付检查

能追溯每分依据；重打/擦网/多打/练习不会混为一谈；最终结果与完整计分链一致或明确列出未解矛盾；所有已约定统计有数字、估值或有依据的不适用说明；比分UI与主剪同源；盘末与末段不会提前进位；真实帧上检查正常分、金球/Deuce、抢七、局盘转场、争议提示与统计页。

复核专项验收：每分单独成片段，连续排列但无捡球、等待和长准备；计数问题覆盖相关全局各分及必要邻接分，不保留连续整局素材。HTML 与时间线均为 R编号在前、P编号在后，逐条对应；右上角局次、发球方符号及姓名持续可见，一发/二发与真实发球序列一致，HTML 每条记录显示相同来源的局次与发球方；左上角同一分编号固定且连续，只有进入下一分才切换，不与局次标题交替；额外说明临时出现在左下角；HTML 脱离视频文件也能独立填写、保存和复制全部结果。用户仅要求更新技能时，只更新保存的技能及相关指引，不改动正在审核的时间线、HTML 或审核草稿。


复核交互验收：HTML 在双方选手列之后、死球类型列之前提供“人工无法确定”列，与双方得分互斥；可保留已知死球原因、保存草稿并完整导出，单独显示人工已复核但待逆推的数量。逆推不把已知终局比分当作创造球果的理由，必须检查约束是否唯一。持拍手的用户确认与默认假设分别记录。
