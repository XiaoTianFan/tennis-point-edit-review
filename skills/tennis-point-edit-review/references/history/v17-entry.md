# 网球逐分精剪、计分与复核

Package integrity: if materialized text is damaged, run scripts/restore_package.py --repair, then scripts/package_check.py before use. The ASCII-safe archive restores local files only; it does not update the saved skill.

用于有连续比赛画面的网球单打录像。支持六局、四局、有占先、无占先、限时不限局、纯抢七及纯抢十；采用用户已给规则和下述默认值，只有影响结果且无法从素材核实的真实缺口才追问。不是比赛裁判或雷达测速工具。双打需要额外确认发球与接发顺序，再扩展规则，不能直接套用单打核算器。

## 当前规范与默认调用
包版本 **2026.10.03-v17**。网球剪辑任务即使用户未手动点选本技能，也应按任务类型检索并加载；未另指定UI技能/模板/风格时，直接复用本包正式模板，禁止随机重设计。优先级为用户当前明确要求、项目已确认风格、本包默认。此为网球工作流默认，不宣称已修改所有视频类别的全局设置。
使用 [正式模板清单](../../examples/ui-manifest.json) 与 [模板说明](../visual-templates.md)，不再将旧示例自由改画。场景、规则或画幅需要适配时保持已确认视觉语言。声明可编辑属性并在目标项目实测后才交付。

## 开始前
开始时先核对是否已有持拍手信息；未给的选手只询问一次“是否有左手球员／双方分别哪只手持拍”。未回答或采用默认设置时，未知选手一律暂按右手，记录 handedness=right、handednessSource=default，并继续工作，不将等待答复作为门槛。已明确为左手或右手的选手沿用已知信息，不重复询问、不被默认值覆盖。后续明确更正时，按真实持拍手重核相关正反手与统计，不机械交换全部标签。

先检查用户已给的录像、附件、选手描述、规则与当前剪辑。按 [输入与规则](../inputs-and-rules.md) 整理赛制、选手身份与发球顺序、已知终场及统计范围。最终比分可以未知，不因此停止分析。

除非用户另有要求，直接采用以下默认值并继续工作，不弹出例行确认表，也不在样例完成后等待批准：
- **开场：** 录像从比赛0:0、第一局第一分的第一次发球开始；普通局初始小分为0:0。首位发球者从画面识别，不凭姓名顺序猜测。
- **结束：** 暂按比赛结束时没有未完成局处理。此为工作假设，需在尾段和计分链核验；不能将“应该没有／presumably”写成已核实事实，也不预先要求用户选择假想未完局的处理规则。
- **样式：** 沿用当前项目已确认的计分板风格；没有已确认风格时直接采用本技能的深蓝／青柠紧凑样式。可生成样例并自行检查，但不将重复批准作为继续制作的门槛。

用户明确说明优先于默认值。若原片或计分链出现具体矛盾，先自行回看相关证据；仅对仍无法解决且会改变结果的问题定向追问，并说明矛盾。默认录像末尾是比赛结束，不擅自标记赛后练习，不补造缺失分，也不从终场比分反推缺失规则。其他未给且确实必要的赛制参数按输入与规则处理；不能因这三项未被逐一回答而暂停。

## 工作流程
1. **建立逐分账本。** 保留源时间、帧率/时间戳和主剪、复核时间线的独立定位。稳定 pointId 不因裁剪、复核排序或删除而改变；发球尝试作为分内子事件。采用 [账本与复核协议](../ledger-and-review.md)。
2. **逐分观察，再精查死球。** 先浏览完整回合，识别双方与真实发球触拍，先排除空挥、活动身体、抛球接回及未尝试击球的重抛，不能按动作外形增加发次或拍数；再在触拍、过网、首次落点和可能二跳附近逐帧检查。用帧差、颜色候选和局部裁切辅助定位，必须回看原图；详见 [判读经验](../adjudication.md)。影像不足才送用户复核，不把常见清晰球批量推给用户。
3. **建立计分链。** 同时记录画面球果、采用判罚、规则进位、现场记法及依据。逐分推进小分、局分、盘分，核对换发球、换边和局末最后有效一分。最终结果只是约束，不能为凑比分擅改球果。冲突时回查整局及邻接边界，不只询问最后一分。
4. **逐分精剪。** 从实际发球动作开始前的紧凑位置起剪，不机械保留固定时长的发球前准备；留到首次死球及必要的对手反应已可辨认。死球尚未确认时，一律按可能仍为活球继续保留，沿源片向后检查并纳入下一拍、球的落点及对手的后续反应；若仍有回球，继续延伸直到明确首次死球或双方进入非比赛状态。禁止在球刚飞起、刚落地、对手尚未作出反应时截断，也不得按固定秒数或未经证实的最后一拍猜剪口。仅在死球已证实后才删除捡球和准备，不能把证据必要的后续反应误删成等待。剪去捡球、等待、发球间准备、一发失误；保留擦网重发并标“擦网”；双误仅保留最后一次发球，发球前仍标“二发”，失误已证实后才改为“双误”。有效发球右上角先标“一发/二发”；统计面板完成后按第9步统一大标签与球速的退出时点。擦网和抛球重抛不消耗新的发球机会。死球后捡球回送不算活球。
5. **解决确实看不清的球。** 在独立复核时间线上排布片段：HTML 每条记录与复核时间线左上角统一按“R编号 / P编号”显示（先 reviewId，后 pointId），同一审核版本共用一份编号映射。时间线右上角常显“第N局 · ● 发球：选手ID/姓名 · 一发/二发”，HTML 每条记录也常显局次、同样的发球方符号与对应发次信息；局次是当前第几局，不是双方局分。必要补充信息临时放左下角；同一分内不因剪口、重发或说明切换而反复跳号，也不再用左上编号与整局标题交替切换来显示局次。记录对应主剪/原片位置、具体疑点及证据。生成可直接打开的独立 HTML 交互列表，给出文件链接和复核时间线名称；HTML 默认只承载交互列表，不嵌入、不附带一份视频，也不为它额外导出视频。局内矛盾需分析整局及邻接边界，并把相关全部候选分逐分纳入；交付时每分单独精剪，删除捡球、等待和发球间准备，禁止用连续整局计分段代替逐分片段；交付复核时间线和 HTML 必须同步。具体显示边界见 [画面与交付](../presentation-and-qa.md)。
6. **回填复核。** 按 pointId 合并而不是行号，检查版本，不覆盖已确认字段为空值。pending/partial 留待核；人工已复核仍无法归属的分使用 unresolved 与 winnerUndetermined=true，得分方留空，转入约束逆推，不当作漏审或不计分；整分 replay 不计分；额外多打与 replay 分开；未勾双误不等于否认双误。复核完毕重新全链进位、重新统计、重建依赖显示；所有行填完不等于计分冲突已解决。
7. **统计与估速。** 逐盘覆盖每位选手的所有真实发球（包括主剪删除的一发失误），每发采用统一口径的初速中心估值，依证据选择近触拍估计、带阻力的飞行反推或明确标注的同组模型补估；不得用区间上界冒充最快值，也不得把少量成功测量代替全盘。 全面计算附件指标，逐一核查每分的发球合法性、接发是否进场以及是否为接发制胜分，分别统计发球直得率和接发进球率，不用最终得分方或第三拍失误替代接发结果；复查所有合法发球的 ACE，而不把用户指出的若干 ACE 当作完整清单。代理自行判读拍数、受迫程度、网前和站位；UE/FE依对手来球造成的压力独立判定，不从移动或站定姿态直接归类。按 [统计口径](../statistics.md) 输出分母、证据、样本覆盖和估算方法。不可用免责声明掩盖编造。
8. **制作统计面板。** 按 [画面与交付](../presentation-and-qa.md) 完成紧凑计分板、发球提示、临时说明及盘末/片尾统计面板，面板与全量逐发初速使用同一份最终统计数据。默认五页各8秒；最高发球初速列为主行，第五页首两行统计 UE 中移动/站定击球的次数。先按[UE/FE判读标准](../error-classification.md)回看来球压力，独立判类后再统计 UE 终结拍动作，不扩成全场逐拍移动标注。定义与训练解释留在底层，面板只呈现统计值和必要的紧凑未知计数。按指标明确的高/低优向用主题青柠色标注较优方，相同数值、无样本和描述性分布不高亮；详见统计口径。
9. **回填逐发球速。** 统计面板制作完成后，将主剪每次保留发球自己的初速中心估值附在现有右上发球标签下方。实际触球、球已出拍后才出现，最多显示3秒，短球随该片段/该分结束或下一次发球开始提前退出；不在抛球准备时预显，不跨分挂留。发球前大标签显示一发/二发，球速出球后才出现；若双误，大标签在已证实失误后改为“二发 · 双误”，不重启计时。大标签和小球速条必须在同一帧退出，退出点为球速出现后3秒与当前片段/该分/下一次发球边界的最早者。此规则仅用于主剪，复核页的局次与发球方仍须常显。默认复用serveLabel和serveSpeed正式模板，保持原标签样式；显示“约 N km/h”，同组补估标“补估”。触拍原帧核实、源片到当前剪辑的时序映射及擦网独立事件处理见 [逐发球速回填](../serve-speed-overlay.md)。
10. **合成验收。** 使用当前环境支持的编辑能力，编辑后检查真实合成画面及依赖层，包括球速出现前后和3秒退出边界。工具成功不等于视觉正确。

## Agent承担核查，减少用户工作量
精细证据、字段来源和依赖重算是agent的内部工作，不新增要求用户逐字段确认的表单，也不把正反手、拍数、UE/FE、站位或估速日常判读转交用户。复核页维持现有简洁结构，已确认信息复用；先自主扩大证据、整局核查和全链复算，再将少量仍无法解决且影响比分/结论的具体问题合并提交，附可检查的证据和推荐判断。
用户确认得分不等于顺带确认所有技术字段；agent在内部维护哪些结论受更正影响并自行重查，不要求用户重新审完整清晰分或整张技术统计表。用户主动要求更细审核时再扩展。
新增内部流程与工具见 [覆盖、谱系及例外接续](../coverage-and-exceptions.md)；[球速异常检查](../../scripts/speed_quality.py) 比较全量/有依据样本均值并提示agent复查最高候选，不产生新的用户问卷。

## 验收底线
能追溯每分依据；重打/擦网/多打/练习不会混为一谈；最终结果与完整计分链一致或明确列出未解矛盾；所有已约定统计有数字、估值或有依据的不适用说明；比分UI与主剪同源；盘末与末段不会提前进位；真实帧上检查正常分、金球/Deuce、抢七、局盘转场、争议提示与统计页。

复核专项验收：每分单独成片段，连续排列但无捡球、等待和长准备；计数问题覆盖相关全局各分及必要邻接分，不保留连续整局素材。HTML 与时间线均为 R编号在前、P编号在后，逐条对应；右上角局次、发球方符号及姓名持续可见，一发/二发与真实发球序列一致，HTML 每条记录显示相同来源的局次与发球方；左上角同一分编号固定且连续，只有进入下一分才切换，不与局次标题交替；额外说明临时出现在左下角；HTML 脱离视频文件也能独立填写、保存和复制全部结果。用户仅要求更新技能时，只更新保存的技能及相关指引，不改动正在审核的时间线、HTML 或审核草稿。


新增验收：HTML 在双方选手列之后、死球类型列之前提供“人工无法确定”列，与双方得分互斥；可保留已知死球原因、保存草稿并完整导出，单独显示人工已复核但待逆推的数量。逆推不把已知终局比分当作创造球果的理由，必须检查约束是否唯一。持拍手的用户确认与默认假设分别记录。


## 复核行始终可见
所有后续 HTML 复核文件都保留“人工无法确定”列。全部记录自打开起常驻列表；不论未复核、选定得分方、人工无法确定、确认死球原因、已完成、待逆推、重打或额外多打，均不自动隐藏、移除、重排或跳离当前行。取消按复核状态隐藏记录的筛选；搜索只高亮与显式定位，不隐藏任何行。改变答案仅更新本行标记、进度与导出，不改变 R/P 顺序和当前滚动位置。 更新正在使用的页面时沿用文件位置、来源/账本版本与草稿键，不清空用户已保存答案。

## 防止复核尾部截断
死球尚未确认时，一律按可能仍为活球继续保留，沿源片向后检查并纳入下一拍、球的落点及对手的后续反应；若仍有回球，继续延伸直到明确首次死球或双方进入非比赛状态。禁止在球刚飞起、刚落地、对手尚未作出反应时截断，也不得按固定秒数或未经证实的最后一拍猜剪口。仅在死球已证实后才删除捡球和准备，不能把证据必要的后续反应误删成等待。 收到剪口不足的反馈，先扩展源片证据再判读或逆推；不能直接重复原短片或只凭总分补结论。主剪和复核片段都要检查最后可见击球后的落点与对手反应；统计更新必须以真正触拍为前提。

新增统计由 [接发汇总助手](../../scripts/serve_return_stats.py) 消费agent逐分视觉标注；模板在证据未齐时拒绝把缺失绘成0。用户不需额外填写接发技术字段，定义与分母见 [统计口径](../statistics.md)。

## 五页统计与低负担补核
默认按总览与关键分、发球与第三拍、接发、回合与击球结果、击球位置与上网排列；使用[诊断汇总器](../../scripts/diagnostic_stats.py)及更新后的[统计口径](../statistics.md)。新增观察由代理承担，不生成逐字段用户审核任务。省略接发深度分布、三个位置的赢分率、重复反向指标；失误方向仅下网/出界。正反手必须回看实际动作，不能复制旧描述或随换边机械互换。
