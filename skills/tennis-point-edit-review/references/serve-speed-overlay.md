# 阶段6：逐发球速图层

消费阶段5同版本的逐发记录与统计面板，使用正式serveLabel/serveSpeed模板。每发显示自己的中心值“约 N km/h”；完成[恢复及拒收](serve-speed-audit.md)后仍不可估，在原发次标签正下方显示纯“N/A”，无“约”、数字、km/h，不进速度均值/最高值，不改变发球机会。pending不是N/A。组均值仅用户明确要求时以“补估”另行展示，默认禁用；不借邻球数字。

## 匹配与时间

按盘/pointId/唯一serveId及源时间识别触拍，用当前剪口、变速与FPS映射。let/重发各有ID，不凭编号顺序匹配；仅给主剪保留的真实触拍加下条，不恢复已删等待/发球，不给重抛/练习造速度。

速度/N/A均在已确认出球的源帧之后出现，不能直接用粗定位或模型触拍。CFR用原帧号/帧率补充微秒映射，防止60000/1001等帧率的微秒取整让标签提前一帧；VFR用实际PTS。非恒速先拆分映射，3秒指成片时长。触拍被裁掉时不移借下一发事件。

共同结束帧取：下条起点+最多3秒、片段结束、该分结束、下一真实发球开始中最早者。现有发次标签从发球前出现，出球后保留并与下条同帧退出，不跨剪口、不挂下一分、不延长素材。右上发次下方等宽、略小字及底部内边距，保持[正式比例](visual-templates.md#组件与默认比例)。

## 双误、let与无触拍例外

准备时仅显一/二发，原帧确认失误/let后才无缝改为“二发 · 双误”或当前发次“· 擦网”，不预告、不换下条、不重计时。判罚确证晚于共同退出点只记outcomeAfterOverlayWindow，不复活标签或提前伪报；结果沿用死球后比分。二发let后仍为二发；其速度只用首次碰网前段，统计纳入范围单列。

真正尝试发球却挥空无离拍速度，也无可核的出球时刻，不走速度/N/A条助手。二发挥空在失误证实后显示双误大标签，最多3秒并随更早剪口/分界退出。复核R/P、局次与发球者是常驻定位信息，不套主剪3秒限制。

## 应用与验收

`serve_overlay.py`按[输入契约](helper-usage.md#发球初速与时序)生成时段，执行层应用到当前编辑器；未知值必须method=unestimated、null及完整unavailableAudit，已拒收部分轨迹不得以数值渲染。默认拒绝model_imputed，显式allow_imputed仅对应用户要求。

全量核一发一记录、状态连续、出球后出现、≤3秒、大小标签共同退出、剪辑变更后映射更新。检查出现前一帧/首帧/末帧/退出后一帧的实际合成，并覆盖长短球、双误、let及N/A。N/A无单位且不漏入均值；最高候选及面板与逐发版本一致。用户无需新增逐发确认。
