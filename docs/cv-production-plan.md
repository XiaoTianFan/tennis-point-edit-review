# 混合视觉网球分析：持续实施与生产验收

状态：进行中。2026-10-25起，此文件是当前执行任务书；此前
[首轮实验](cv-research-milestone.md)的有界停止条件已被用户替换，测量仍保留。
目标是在完整现存成片语料上，交付与默认agent路线实用品质相当或更好的
可选CV+agent模式，降低总分析/复核时间与token，集成现有Courtside/Edit。
单次试验、报告、提交或上下文结束均不是生产目标完成条件。

## 执行指令

在原始检出持续执行“建基准→研究候选→复现→测量→诊断→修改→回归→
保留/淘汰”的循环。先检查实际成片库及全部相关后代，不用此前的单个
已剪输入代替。完整原录像已删除不阻塞现存成片作为直接输入。

所有现存视频都登记身份、PTS、时长、关联记录和映射状态；记录不完整
的样本进入单列评价类别。读取规范项目、export、账本、review、contacts、
bounces、统计和程序记录，使用已有迁移表解析旧路径，不改写历史。
按独立比赛/原录制分组，替代成片与发球合集不得跨开发/验证/留出分组。
清点覆盖全部库，最终方案处理全部可用整场，分层评估容易与困难样本。

既有agent记录是用户指定的实践参考，不要求先建立完美独立真值。冲突
在现存画面上针对性核查，新增版本化修正；不覆盖旧结果。推理入口只给
视频与独立运行配置，评价端才读取历史答案。比分只能作一致性约束。
剪口不是发球或死球；OCR/图层如使用，须独立开关与消融，不暗中泄漏答案。

研究和实际运行多种可信框架，核对预处理、时序、权重、授权与机位域。
隔离配置GPU环境，保留全局环境和其他服务；公开模型与普通本地实验可
直接执行，不购买云资源。每次改变写假设、固定开发集、错误分析、资源/
覆盖/延迟/复核变化，保留最好配置和可回退版本。

逐步完成球场几何、球候选/轨迹、触拍/落点、发球/活球/死球、分/回合
提案、有证据支持的统计及agent例外处理。未知仍保留，但广泛拒判是要
降低的错误负担，不能用全部拒判或回退全量原流程通过验收。

长视频须有进度、分块、恢复、输入/配置指纹、资源界限与明确失败；
观察、推断、agent采用和用户批准分层。完整导入→分析→复核→保存→
重开及隔离测试渲染均需实测。保留既有七套模板、源PTS、原生精确证据、
legal-serve分母和一次视频/音频编码契约。内部测试输出不冒充用户成片
批准；原片/现存成片不改写；破坏性清理和正式交付仍按原授权边界。

阶段性改动本地提交并更新操作文档，不新建worktree、不远程发布、不
同步账户Skill。实验/权重/视频/私有标签在主检出ignored outputs中。
遇到性能差或误检继续诊断；仅真实外部前提导致无法做任何有意义工作时
提出具体问题。不要以“有条件可行”“需要进一步研究”结束可执行工作。

## 验收矩阵与冻结程序

下列是预登记工程目标，不是已达成结果。先在开发集测当前agent基线和
可用参考误差，冻结数值与理由，再解封留出集。基线若揭示标签分辨率
不支持某指标，应改为明确可测指标并留版本历史，不能为迁就差结果降低
目标。留出一旦用于调参即转为开发数据，后续用独立组交叉验证。

| 门 | 预登记要求 | 证据 |
|---|---|---|
| G01 语料完整性 | 实际目录100%视频登记；完整整场100%处理或有具体外部失败原因，不能静默剔除 | 版本manifest、输入哈希与PTS覆盖 |
| G02 参考/泄漏 | 所有采用标签有来源与映射状态；推理不读规范答案；同比赛分组无泄漏 | 独立inference/evaluation输入清单与hash |
| G03 球定位 | 分层含正负例、每组可见球评价；初始目标10px容差F1≥0.90，逐组报告，不能只报有值均值 | 固定采样、可见/遮挡/未知分层、错漏分布 |
| G04 几何 | 支持机位每段可稳定标定；保留验证点中位误差≤5px、P95≤10px；初始设置≤2分钟/机位 | 未用于拟合的点、相机变化验证；无米制精度冒称 |
| G05 事件 | 可观察的触拍/落点初始目标P/R均≥0.90、时刻容差50ms；不可观察分层 | 一对一事件匹配、误检/漏检和时间误差 |
| G06 分边界 | 发球/首次死球初始召回≥0.95、精度≥0.90；起点0.5秒、结束0.2秒容差；不使用编辑剪口代替 | 全场事件参考、截断状态、前后核查 |
| G07 最终质量 | 混合流程修正后有效分归组/采用赢家与可信参考一致；冲突须有原生证据；无静默漏分 | 完整逐分链与差异复核，未知独立计数 |
| G08 统计 | 有支持的统计修正后与同版本规范计数一致；不同定义/旧模型填补单列；未知/N/A不制造分母 | 逐项差异、事件谱系、legal-serve约束 |
| G09 效率/复核 | 固定配对任务实测总墙钟及可用token≤agent基线50%；需视觉例外核查的事件≤25%，修正量单列 | 解码/推理/证据/agent/用户分别计时；token缺测不能报通过 |
| G10 运行可靠性 | 全场完成、可恢复且不重复/漏帧；源/配置变化拒绝混用；资源可控、错误可诊断 | 完整运行、一次中断恢复、指纹与失败测试 |
| G11 工作台/渲染 | 全场导入、定位、复核、保存、重开、隔离测试渲染通过；旧工程与批准不改写 | 浏览器/API记录与源绑定测试输出 |
| G12 分发/维护 | 依赖/模型来源版本可复现、授权可分发或外置；包验证/构建通过；默认agent路线可用 | 安装说明、版本锁、测试与本地提交 |

目标不要求单目自动裁判或100%机器正确，但G07/G08最终可用结论、G09
成本和复核负担不能靠全部交还原流程满足。原始未剪录像的泛化另列；
不能把成片试验宣称覆盖已经删除的等待过程。
