## 冻结的基线与范围

2026-10-25 在原始检出目录开始；Git 基线 `40caab4`，工作树干净，技能
`2026.10.22-v26.1`。默认 agent 主导的全覆盖视觉分析继续受支持；此次是
显式启用的研究路线，不能改变比赛答案、统计分母、剪口或导出批准。
七个正式 JSX 模板不变。不发布远程仓库，不同步账户技能。

现有可复用能力包括源 SHA-256/PTS 绑定、原生 ROI、阶段缓存、渲染剪口
扫描、局部 HSV/运动候选、球场几何与发球物理估计、稳定 P/R 编号、
Courtside/Edit JSON 计划与复核、统计和一次视频/音频编码的原片导出。
精确事件仍须原生像素与相邻 PTS；剪口检测不等于网球分识别。

本地找到五个旧候选检出及已下载权重。候选目录中存在修改，研究只读，
不更新其依赖或代码。当前 Python 为 CPU PyTorch；有独立 GPU，但尚无
已验证 GPU 推理环境。首轮限短窗口推理，不训练模型、不下载大型数据集。

首轮语料为现存成片及对应规范 agent 记录。用户确认早期完整原片已删除，
不需要恢复；四个旧原片路径不可用不构成研究阻塞。一个历史已剪输入仍在。
所有私有路径、哈希、工程 revision、边界、答案和模型文件指纹保存在独立
任务目录的 `audit/baseline-inventory.json`，不进入版本库。旧记录中的
球路和事件是 agent 标签；现场计分确认不等于球像素/落点真值。尚无独立
测量球轨迹、同步多机位或盲测标注。缺少的数据不能按零误差报告。

## 首轮验收范围

1. 固定上游版本，检查代码/权重授权、输入假设及维护信号。
2. 短窗口原片解码 → 球/球场候选 → 保守轨迹与事件提案 → 原生证据 →
   现有工作台中的未确认复核计划。所有观察、推断、采用判断分层。
3. 对照可用 agent 标签，测运行成本、覆盖/拒判和定位差异；没有可信
   参考的指标明确未测。不给单目画面承诺厘米精度、可靠判线或跨视频精度。
4. 提供可运行接口、操作文档、针对契约的验证、结果报告与有条件建议。

新增代码只分发本仓库实现；未明确授权的第三方模型代码和权重不打包。
研究可显式加载用户已有本地模型，记录代码与权重哈希。未来可替换后端，
不让一个模型库控制编辑、评分或统计状态。

成片以独立 SHA-256/PTS 时钟作为新证据源。旧源事件必须通过当前 clip
顺序、trim、fps、hold 和可用导出元数据映射到成片；核查输出长度与关键
画面，记录映射置信与不可映射项。成片上的发球起始/首次死球识别与编辑
剪口检测分别评估。删去等待、图层、接缝可能影响模型；不能据此推断
完整原录像的空闲筛除或整场分割已验证。目标是相对当前工作流的实用
精度与成本改进，独立真值不是继续实验的前置门槛。

## 交付结论

**可以继续作为可选证据助手试验，不能据此替代当前 agent 流程。** 已跑通
输入身份/PTS → 球与球场候选 → 保守轨迹/落点提案 → 原生证据 → 现有
Courtside/Edit 未确认工程。当前包为 `2026.10.25-v26.2`；接口、依赖和
契约见[操作说明](../skills/tennis-point-edit-review/references/optional-vision.md)，
固定版本的上游研究见[组件研究](cv-component-research.md)。

两段合计15秒、900个不同源帧的实验中，学习模型在30个已选可见球正例上
有24个选定位置距本轮 agent 标注不超过5像素；4个拒判，2个明显误跟踪。
A段产生一个与历史 agent 落点夹逼窗相符的提案，B段没有形成落点提案。
CPU模型处理耗时733.87秒，尚未证明总成本或效率优于 agent。球场标定
全部拒判，发球起始、首次死球、整分边界和技术统计均未自动建立。

这个结果支持继续改进检测与核查接口，不支持自动判线、厘米精度、无人
审核整场剪辑或跨视频可靠性的承诺。所有候选仍为未采用状态；本轮不
修改旧比赛答案、统计分母、剪口与批准，也不导出新的比赛成片。

## 实现与资源

新增四个独立接口：`cv_pipeline.py` 负责有界扫描/交接，
`cv_observations.py` 提供候选与几何，`cv_reference.py` 映射历史标签，
`cv_evaluate.py` 做同源PTS正例对照。HSV/运动为廉价对照；学习后端显式
加载用户已有的本地TrackNet和14点球场模型，不自动安装、下载或训练。
额外CatBoost只做关闭插值的落点探针。

原始候选、选定轨迹、推断事件、采用判断分层保存。缺球、多候选、跳变、
相机配准不足及几何不一致均可拒判；没有用插值补成观测。轨迹转折只称
`bounce_candidate`，保留触拍、误跟踪等解释；`adjudication=null`。
窗口不是分，`serveOnset`、`deadBallEnd`为null；统计为`not_qualified`。

机器为i9-13980HX、约31.6GiB RAM、RTX4080 Laptop 12GB；本轮实际使用
CPU PyTorch 2.2.2、8线程，未配置或验证CUDA。Python3.11.4、PyAV10、
OpenCV4.12、NumPy1.26.4；CatBoost探针使用已有Python3.12环境。各run记录
实际依赖版本、配置、源/代码/权重指纹。没有联网模型推理或API调用；
这不代表研究过程或后续 agent 核查没有成本。

任务产物约24MB量级，含工作片段、证据和审计；没有复制大模型或全量源片。
A证据阶段结束时发现受保护的B观察文件仍在变化，缓存清理守卫停止了
该次收尾，未删除数据。A必要图像另行逐文件校验复制到保留目录，旧阶段
仍在；B证据正常提升。未修改不可变清理计划来绕过守卫。

## 实测结果

### 运行时间与覆盖

每一后端处理相同A/B帧；因此不同源帧为900，四次扫描总计1,800帧。
“有候选”不是正确检出，“选定轨迹”也不是核验通过。

| 案例 / 后端 | 帧数 | 有候选帧 | 选定轨迹帧 | 落点提案 | 墙钟秒 | 进程CPU秒 |
|---|---:|---:|---:|---:|---:|---:|
| A / HSV+运动 | 390 | 369 | 30 | 0 | 14.40 | 14.05 |
| A / 本地TrackNet | 390 | 154 | 150 | 1 | 321.50 | 2131.16 |
| B / HSV+运动 | 510 | 508 | 0 | 0 | 12.06 | 11.92 |
| B / 本地TrackNet | 510 | 143 | 134 | 0 | 412.37 | 2774.27 |

学习后端合计733.87秒，约1.23帧/秒、约49倍视频时长；廉价对照26.46秒。
多线程进程CPU秒可大于墙钟秒。旧 agent 流程的同样窗口耗时、token、
人工/agent修正时间，以及峰值内存未有可比测量，保留null；不声称节省
多少时间或费用。各run墙钟包含源身份核查、初始化与扫描；后续复核另计。

### 球位置：正例抽查而非全片精度

回看37张未经缩放的原生ROI，在其中30帧可见球上读取中心：A18帧，标注
不确定量约±3像素；B12帧，约±4像素。标注前已看到模型/历史位置，**非
盲测、非独立真值**。B另外7帧未形成可靠球标签，未当作负例。没有逐帧
标完900帧；不报告全片precision/recall或真阴性。

| 后端 / 案例 | 正例数 | 选定位置≤5px | 拒判 | 选定但>5px | 有值误差中位数 / 最大值 |
|---|---:|---:|---:|---:|---|
| TrackNet / A | 18 | 17 | 1 | 0 | 1.43 / 2.37px |
| TrackNet / B | 12 | 7 | 3 | 2 | 2.55 / 293.67px |
| HSV+运动 / A | 18 | 2 | 15 | 1 | 2.00 / 303.64px |
| HSV+运动 / B | 12 | 0 | 12 | 0 | 未测 / 未测 |

TrackNet合计24/30、廉价对照2/30达到5px阈值。原始候选中事后取最近球点
分别为26/30和11/30；这是乐观的候选覆盖，不是系统实际选点表现。B有
一帧正确原始候选存在但跟踪仍选错，随后又拒判，说明轨迹选择还有明显
改进空间。5/10/15px三个阈值在本小样本得到同样计数；不把像素数换算为
厘米，也不因有值中位数较小就忽略拒判和严重错点。

### 落点、场地与分边界

| 项目 | 历史参考 / 当前结果 | 判断 |
|---|---|---|
| A落点 | 历史估计2.15173秒，夹逼[2.11833,2.18513]；模型2.13547秒，像素(1147.5,541.5) | 相差约−16.27ms且在参考窗内；连续原生ROI支持转折，仍为待采用提案 |
| B落点 | 映射参考1.57587秒；原生图像约1.5515–1.5849秒支持转折 | 模型附近有缺失与误跟踪，未满足连续支持帧，明确无提案 |
| CatBoost探针 | 禁止样条/插值，按剪口分段；A一次响应，B零次 | 没有解决B缺口；原训练帧率对当前60fps的适用性未验证 |
| 自动场地 | A10次、B12次采样，0/22通过几何守卫 | 无有效球场坐标；不是“场地误差为零” |
| 显式场地标定 | A六点拒判；八点拟合曾靠RANSAC丢弃右侧边线形成候选 | 右侧残差61.9/102.5px；新增整组矛盾点守卫，最终拒判，旧结果已标为被替代 |
| 发球起始/首次死球 | 两窗均拒判，未建立自动分起止 | 没有分边界准确率或零误差结论 |

每个窗口还产生三个视觉不连续提案。A在5.85585秒、B在7.8078秒与已有
剪口一致；另四处未对应已知剪口。这里只找回两个已知编辑边界，不能
称六次网球事件，也不把剪后下一段开头用作前一分死球证明。

失败分布目前只覆盖两个短窗口：低机位与图层、球像素小/模糊、衣服等
误候选、间断轨迹、场线几何矛盾。近端/远端、不同比赛、遮挡与曝光的
分层样本还不足以推断普遍性能；整场统计、赢家与合法发球速度均未计算。

## 复现和工作台交接

保存的配置与结果分别为 `analysis/config-A.json`、`config-B.json`、
`classical-A.json`、`classical-B.json`，以及同名加 `-run1` 的目录。
`audit/benchmark-summary.json`汇总测量，`agent-spotcheck-A/B.json`
保存正例参考；`comparison-*.json`包含逐PTS误差。每次重跑必须用新目录。

在仓库根目录的PowerShell中，例如：

```powershell
$visionScripts = Join-Path (Get-Location) 'skills/tennis-point-edit-review/scripts'
$pilot = Join-Path (Get-Location) 'outputs/cv-pilot-20261025'
$cases = Get-Content (Join-Path $pilot 'audit/corpus.json') -Raw | ConvertFrom-Json
python "$visionScripts/cv_pipeline.py" scan $cases[0].source "$pilot/analysis/repeat-A" --config "$pilot/analysis/config-A.json"
python "$visionScripts/cv_evaluate.py" "$pilot/analysis/repeat-A/result.json" "$pilot/audit/agent-spotcheck-A.json" "$pilot/analysis/comparison-repeat-A.json"
python "$visionScripts/cv_pipeline.py" plan "$pilot/analysis/repeat-A/result.json" "$pilot/media/A-working.media.json" "$pilot/analysis/players-A.json" "$pilot/analysis/plan-repeat-A.json"
python "$visionScripts/local_editor.py" init "$pilot/analysis/plan-repeat-A.json" "$pilot/edit-repeat-A"
python "$visionScripts/local_editor.py" serve "$pilot/edit-repeat-A" --open
```

首次完整实验的代码hash与两份代码快照保存在 `audit/run1-code.json` 和
`audit/run1-cv_*.py`；后续加强了标定、输入和外部模块载入守卫。**完整
计时属于保存的run1代码**，不是宣称提交版全部重跑过。改后另做0.5秒/
30帧学习后端烟测：24帧候选、23帧轨迹、一个落点提案，墙钟27.42秒；
随后只禁用了外部模块导入产生字节码。当前命令使用提交版重跑并生成新
指纹。私有README提供证据索引和历史快照重放方法。

创建了独立 `edit-A` / `edit-B`，使用绑定当前输入的工作片段。浏览器
核验了中文页面、播放至窗尾、逐帧定位、完整/复核视图切换，A备注保存
重载和交给agent导出。A/B仍为0/1复核完成、赢家null、批准为空。A备注
仅记录接口验收。没有让用户重新承担原比赛全场审核，也没有修改旧工程。
UI沿用“分”的通用计数文案，行内明确“实验窗口，不代表一分”；CV编号

## 下一轮建议与停止条件

1. 在同样帧、同样拒判政策下比较WASB网球checkpoint与当前模型，先验证
   可用GPU/ONNX环境；分别测安装/冷启动、稳定推理、内存和复核修正时间。
   条件是权重来源/条款与运行环境明确，不能用GPU理论性能冒充实测。
2. 从已映射的现存成片选约20个事件，分层覆盖远近端、遮挡、图层、失败
   发球和不同比赛；先记录采样规则，再比较旧agent记录与新候选。继续
   允许agent修正参考，保留修正前后，不以独立真值作为启动门槛。
3. 场地优先核对点位定义、镜头畸变和低机位可见性，用保留点验证几何；
   几何未通过时停止米制坐标输出。人物位置/动作语境随后用于触拍、
   发球准备与死球解释，不能仅以球轨迹转折或视频剪口切分比赛。
4. 为相同工作量记录agent实际耗时/token、CV耗时、人工与agent修正量，
   比较最终可用证据和总成本；只有覆盖、错误风险及复核负担均改善，才
   考虑扩大默认使用范围。整段未剪原录像的找分验证留待未来有新素材。

当时的有界试验已完成；其停止条件已被用户明确替换。模型引入、完整
成片语料、几何与事件识别、效率测量和生产化现在都是持续任务内的必做
工作，按生产验收任务书推进；本报告不会提前把它们记为已解决。
