# Fresh-agent Premiere acceptance test

This is a repository-maintenance test protocol. Match semantics still come
from the current portable skill and its references. Keep filled prompts, media,
machine paths and detailed results in ignored local output.

## Scope

The next test starts with a new agent context, the raw recording and a newly
created Premiere project. Old diagnostic projects, rendered overlays and cut
plans are not starting material. Record the repository commit, package version
and template hashes actually loaded; an installed account copy may be older.

For this next run, the owner authorized **rendered graphics**, with native
editable text marked pending. The general hybrid preference is unchanged.
Canonical JSX produces transparent PNGs; Premiere controls timing and opacity.
Text changes require regeneration. Do not claim this qualifies native MOGRTs.

## Setup and independence

- Read the package's environment, Premiere and graphics references. Detect the
  installed host/build and use the corresponding CEP or UXP branch. A newer
  host does not inherit an older host's live test results.
- Use terminal/files only. Source-frame extraction and visual media inspection
  are required, but desktop clicking and keyboard simulation are excluded.
  Metadata alone cannot establish tennis outcomes.
- Start from the actual reset record. If the test bridge was removed, install
  and configure it afresh using the skill's documented process and a stable
  local tool directory. Preserve unrelated settings, record prior values and
  pin the package/version. Do not reuse a private investigation driver.
- If a bridge was retained, label installation as reused, not freshly tested.
  Existing Adobe/Node/Python/FFmpeg installations are also reused prerequisites.
  Do not reinstall Adobe or alter its licensing to manufacture a clean machine.
- First activation of a host panel may require a specific user action. Ask for
  that action when needed; do not invent terminal access to an unloaded panel.
  Installation, connection and actual editing are separate gates.
- Create a new output root and scratch project. Guard mutations by project path
  and sequence identity. Inspect unknown outcomes before retrying. Preserve
  the raw recording, reference export and reference editor project.

## Execution gates

1. Run a small synthetic host proof: import, exact frame ranges/timebase,
   stereo, transparent overlay, actual export, save and reopen.
2. Analyze the full raw recording through all eight skill stages. Retain source
   coverage, stable point IDs, review states and original evidence timestamps.
   Derive statistics and serve estimates with the actual helpers; do not
   fabricate outcomes or numbers to complete a test matrix.
3. Export a representative real excerpt from the new analysis before building
   the full sequence. Exercise relevant score, serve and speed changes. Use
   labeled synthetic cases for edge cases absent from the real recording.
4. Probe VFR and preserve the original source-time mapping when producing
   same-rate CFR media. Build Premiere tracks through bounded FCP7 interchange
   plus verified host operations, or another demonstrated terminal adapter.
   Account for every pending post-import operation.
5. Freeze and hash the independent first-pass ledger, score audit, cut plan,
   statistics, speed evidence and graphics manifest before opening optional
   comparison references. Compare by source time/event identity. Keep the
   pre-comparison version and investigate differences in the raw recording;
   never force a new result to match an old score or statistic.
6. Verify all media online, base-track coverage, linked audio ranges, frame
   boundaries, overlay states and five statistics pages. Save, reopen and read
   back. Decode the actual finished export and inspect composition, typography,
   timing, stereo/gain/sync and duration. A queued export is not completion.
   Listen across representative cuts if possible; otherwise leave subjective
   listening explicitly pending for the owner.

## Delivery

Deliver a clean native project, watchable Premiere export, dependencies and
source-time manifest, the skill-required ledger/review/statistics artifacts,
and one clear review starting point. Synthetic test sequences stay outside the
main review project. An XML file alone is not a completed Premiere edit.

Report these gates separately: fresh-agent skill loading; setup performed or
reused; exact host/backend; full-source analysis; rendered-graphics QA; native
editable graphics; newer UXP; listening; owner acceptance. Native graphics and
newer hosts stay pending unless actually tested. Do not infer human acceptance
from automated checks.

Preserve minimal reproductions of defects. A test run does not authorize
silently changing the specification, synchronizing an account Skill or
publishing. Any separately authorized package fix needs focused verification,
package refresh/validation and its own local commit.
